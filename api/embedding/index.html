    Embedding¶

    embed_for_matching encodes patient summaries and cohorts with TrialSpace, a single-vector Sentence Transformer, into one vector space. generate_candidate_matches then ranks pairs by cosine similarity (see candidate matching). Cosine similarity is a ranking score, not a probability or a determination of eligibility.

    Inputs and outputs¶

    Retrieval reads key text only, never boilerplate:

    entity_type Identifier Text embedded (first column present)
    "patient" patient_id cancer_history_summary, the summary's key section; else the key section of a complete patient_summary (the text before Other relevant history:)
    "trial" cohort_trial_id (or historical space_trial_id) cohort_key_criteria; else cohort_eligibility_criteria, when remove_boilerplate_criteria did not run; else historical clinical_space_summary

    Cohorts from process_trials have cohort_key_criteria. TrialSpace models from the training pipeline learn from merged cohorts' key criteria and patients' key sections, so inputs prepared the same way match their training.

    The result has the identifier column and embedding, one L2-normalized float32 vector per row (a list of floats), in input order. With return_metadata=True it also returns a metadata dict with package, config_snapshot and model_metadata["embed_for_matching"] (the model's model_name and model_sha).

    from matchminer_ai import load_preset
from matchminer_ai.embedding import embed_for_matching
from matchminer_ai.matching import generate_candidate_matches

config = load_preset("default")
config.embedding["model_path"] = "/path/to/trialspace"
patient_vectors = embed_for_matching(patients, entity_type="patient", config=config)
cohort_vectors = embed_for_matching(cohorts, entity_type="trial", config=config)
cohorts_for_each_patient = generate_candidate_matches(patient_vectors, cohort_vectors, k=20)
patients_for_each_cohort = generate_candidate_matches(cohort_vectors, patient_vectors, k=50)

    embed_texts(texts, config=config, entity_type="patient" | "trial") embeds plain strings and returns the vectors and the model metadata. Without entity_type it uses the model's shared query prompt.

    Model and settings¶

    The embedding configuration section selects the model and how it encodes. The preset's model_path is a local TrialSpace checkpoint that is not published (google/embeddinggemma-2 fine-tuned by the training pipeline), so set it to your own. A local path that is missing or unreadable raises FileNotFoundError; embedding never falls back to another model.

    Key Default Meaning
    model_path a local checkpoint TrialSpace directory or Hugging Face model ID
    device cuda One device
    dtype, autocast float32, bfloat16 Weight precision; autocast precision, applied on CUDA only
    prompt_profile trialspace Per-side prompts (see below)
    default_prompt_name SentenceSimilarity The model's default prompt
    include_prompt_in_pooling true Mean pooling over the prompt and the text
    text_only true Load EmbeddingGemma 2 without its vision and audio towers
    batch_size 32 Texts per batch
    max_seq_length 4096 Truncation length in tokens (required)
    prompt_file embedding.txt The query prompt for a model that saved none and has no prompt profile

    These keys map onto EncoderSettings, so embed_for_matching encodes exactly as the training pipeline's mining does, on one device. The configuration reference describes each key. Autocast runs on CUDA only, so CPU vectors are float32 throughout and differ slightly from CUDA vectors. The encoder identity records which was used.

    Prompts¶

    A TrialSpace model from the training pipeline saves one prompt per side: patient_summary for patients and this_space for cohorts. Each side is encoded with its own prompt. prompt_profile: trialspace applies embedding.trialspace_contract.model_prompts("trialspace"), which gives the same prompts: the prefix task: sentence similarity | query:, the retrieval INSTRUCTION, then Patient history: or Cohort eligibility criteria:. trialspace_contract also holds the prompt names (PATIENT_PROMPT, COHORT_PROMPT) and the retrieval DIRECTIONS shared with training.

    Prompts are prepended exactly, as in training. embedding.inference.count_embedding_tokens counts the same text.

    A model without side prompts and without a prompt_profile encodes both sides with its saved query prompt, or with prompt_file when it saved none.

    Other TrialSpace models¶

    The published ksg-dfci/TrialSpace-0526 (based on Qwen3-Embedding-0.6B) was trained on a different text format, cancer_history_summary and clinical_space_summary. To use it, set model_path to it, remove the EmbeddingGemma 2 settings (dtype, autocast, prompt_profile, default_prompt_name, include_prompt_in_pooling, text_only), and set max_seq_length to the model's limit.

    Never mix vectors¶

    Vectors from different models or encoding settings are not comparable. When you change the model, embed both sides again. Use an immutable checkpoint path or Hub revision, and restart the process after replacing a model at the same path, because loaded models are cached per process.

    model_metadata names the model by its Hub SHA, or a local directory by a digest of its files' sizes and times. Stored vectors that the package reuses carry a fuller encoder identity and are never reused when it differs: the guideline embedding cache of retrieve_guideline_considerations and PatientEmbeddings from embed_guideline_patients (see guideline retrieval). That identity covers a digest of the loaded weights for a local directory (with its training stage receipt), the encoding settings, tokenizer, prompts and library versions.

    def embed_for_matching(
    df: pd.DataFrame,
    *,
    entity_type: Literal["patient", "trial"],
    config: MMAIConfig | None = None,
    return_metadata: bool = False,
) -> pd.DataFrame | tuple[pd.DataFrame, dict]:
    """Encode key patient/cohort text with TrialSpace for bidirectional retrieval.

    Retrieval reads key text only, never boilerplate. Patient rows require
    ``patient_id`` and the summary's key section, ``cancer_history_summary``
    (when only a complete ``patient_summary`` is given, its key section is taken:
    the text before ``Other relevant history:``). Trial rows require
    ``cohort_trial_id`` and ``cohort_key_criteria`` (the cohort's criteria without
    its boilerplate, from ``remove_boilerplate_criteria``); without the boilerplate
    step, ``cohort_eligibility_criteria`` is embedded, and historical
    ``space_trial_id`` / ``clinical_space_summary`` remains accepted.

    Returns the identifier and one embedding vector per row. ``config.embedding``
    selects the checkpoint, device and context. A TrialSpace model that saves
    patient and cohort prompts gets them for each side. With
    ``return_metadata=True``, also return the configuration and model fingerprint.
    See docs/api/embedding.md.
    """
    summaries = _resolve_texts(df, entity_type)

    id_cols = _resolve_id_columns(entity_type)
    if entity_type == "trial" and "cohort_trial_id" in df.columns:
        id_cols = ["cohort_trial_id"]
    missing = [col for col in id_cols if col not in df.columns]
    if missing:
        raise ValueError(f"df is missing required columns for {entity_type}: {missing}")

    resolved_config = config or load_default_preset()
    output = df.copy()
    embeddings, model_metadata = embed_texts(summaries, config=resolved_config, entity_type=entity_type)
    output["embedding"] = embeddings
    result = output[id_cols + ["embedding"]].copy()
    if return_metadata:
        metadata_payload = {
            "package": package_metadata(),
            "config_snapshot": config_snapshot(resolved_config),
            "model_metadata": {
                "embed_for_matching": model_metadata,
            },
        }
        return result, metadata_payload
    return result

    Large encoding jobs¶

    open_encoder(EncoderSettings(...)) encodes many texts at once and returns float32, L2-normalized NumPy vectors in input order. The training pipeline's mining uses it, and embed_for_matching loads and encodes with the same functions on one device.

    • One device (devices=("cuda:0",)): the model's own encode.
    • Several devices (devices=("cuda:0", "cuda:1", ...)): one spawned worker process per device. The coordinator takes the model's own length order and deals out the batches a one-device run would form, so every text is encoded in the same batch and the vectors equal the one-device vectors on the same GPU type.
    • vLLM servers (backend="openai"): OpenAI-compatible /v1/embeddings servers, given as remote={"server_urls": [...]} or a server_urls_file registry. vLLM 0.32 and later serve EmbeddingGemma 2 natively; matchminer_ai.llm.vllm_server.build_embedding_server_command builds the vllm serve <model> --runner pooling ... command (one server per GPU). The client prepends the prompt, truncates and tokenizes exactly as sentence-transformers does, sends token IDs to the least-loaded server, and normalizes. vLLM's kernels and bf16 weights give vectors close to (about 0.999 cosine), not equal to, the local backends'.

    encoder_identity(settings) names everything that changes the vectors (backend, model and revision, prompts, length, precision, batching) and no paths or devices. Store it with the vectors and never mix vectors with different identities.

    from matchminer_ai.embedding import EncoderSettings, open_encoder
from matchminer_ai.embedding.trialspace_contract import COHORT_PROMPT, PATIENT_PROMPT, model_prompts

settings = EncoderSettings(
    "google/embeddinggemma-2", revision="914f7f89142e33e77833254d9c9b90c3cef7303b",
    devices=tuple(f"cuda:{i}" for i in range(8)), batch_size=32, max_seq_length=8192,
    dtype="float32", autocast="bfloat16", prompts=model_prompts("trialspace"),
    default_prompt_name="SentenceSimilarity", include_prompt_in_pooling=True, text_only=True,
)
with open_encoder(settings) as encoder:
    patient_matrix = encoder.encode(patient_key_texts, PATIENT_PROMPT)
    cohort_matrix = encoder.encode(cohort_key_texts, COHORT_PROMPT)

    matchminer_ai.matching.retrieval.score_batches is exact search over such vectors in query batches, on one or more devices. Every batch is scored against every document, so the scores do not depend on the number of devices. stable_top_k breaks ties by document index.

    matchminer_ai.embedding.encoder ¶

    Sentence-transformers encoding on one or more devices, or over vLLM embedding servers.

    :func:open_encoder returns an encoder whose encode(texts, prompt_name) gives float32, L2-normalized vectors in input order:

    • one device: the model's own encode (it sorts the texts by length and encodes batches of batch_size);
    • several devices (devices=("cuda:0", "cuda:1", ...)): one worker process per device. The coordinator takes the model's own length order and deals out the same batches the one-device encoder would form, so every text is encoded in the same batch as on one device and the vectors match it (on the same GPU type);
    • backend="openai": OpenAI-compatible /v1/embeddings servers (vLLM >= 0.32 serves EmbeddingGemma 2 with vllm serve <model> --runner pooling; see :func:matchminer_ai.llm.vllm_server.build_embedding_server_command). The client applies the prompt and truncation exactly as sentence-transformers does, sends token ids, and normalizes; vLLM's kernels and bf16 weights give vectors close to (about 0.999 cosine), not equal to, the local backends'.

    :func:encoder_identity names everything that changes the vectors and no paths, hosts or devices, so vectors made by different backends or settings are never mixed. Training's mining encodes with this module, and embed_for_matching loads and encodes with the same functions (one device), its embedding configuration section giving the settings.

    @dataclass(frozen=True)
class EncoderSettings:
    """What is loaded and how it encodes.

    ``model`` is a Hub id or a local directory; ``model_identity`` replaces it in the identity (for a local
    checkpoint, the id of the stage that wrote it). ``prompts`` overrides or adds named prompts (for
    example the TrialSpace profile, ``trialspace_contract.model_prompts("trialspace")``). ``text_only``
    loads EmbeddingGemma 2 without its vision and audio towers. ``dtype`` sets the weights' precision and
    ``autocast`` the CUDA autocast precision; None keeps the model's and disables autocast.
    """

    model: str
    revision: str | None = None
    cache_dir: str | None = None
    devices: tuple[str, ...] = ("cpu",)
    batch_size: int = 32
    max_seq_length: int | None = None
    dtype: str | None = None
    autocast: str | None = None
    prompts: dict[str, str] = field(default_factory=dict)
    default_prompt_name: str | None = None
    include_prompt_in_pooling: bool | None = None
    text_only: bool = False
    model_identity: str | None = None
    backend: str = "sentence_transformers"
    # backend "openai": server_urls or server_urls_file (a {"servers": [{"url": ...}]} registry),
    # model_name (served name; default the first /v1/models entry), max_concurrent_per_server,
    # request_batch_size, request_timeout, max_retries, api_key_env.
    remote: dict[str, Any] = field(default_factory=dict)

    def __post_init__(self):
        if self.backend not in ("sentence_transformers", "openai"):
            raise ValueError("Encoder backend must be sentence_transformers or openai")
        if self.batch_size < 1 or not self.devices:
            raise ValueError("Encoders need a positive batch size and at least one device")
        if self.dtype not in (None, "float32", "bfloat16") or self.autocast not in (None, "bfloat16"):
            raise ValueError("dtype must be float32 or bfloat16 and autocast bfloat16, or None")
        object.__setattr__(self, "devices", tuple(self.devices))

    @contextmanager
def open_encoder(settings: EncoderSettings) -> Iterator[Any]:
    """An encoder for ``settings``: vLLM servers, several worker processes, or this process."""
    if settings.backend == "openai":
        encoder = OpenAIEmbeddingsEncoder(settings)
    elif len(settings.devices) > 1:
        encoder = MultiDeviceEncoder(settings)
    else:
        encoder = LocalEncoder(settings)
    try:
        yield encoder
    finally:
        encoder.close()

    def encoder_identity(settings: EncoderSettings) -> dict[str, Any]:
    """Everything that changes the vectors (backend, model, revision, prompts, length, precision, batching)."""
    identity = dict(implementation=IMPLEMENTATION, backend=settings.backend,
                    model=settings.model_identity or settings.model, revision=settings.revision,
                    max_seq_length=settings.max_seq_length, prompts=dict(sorted(settings.prompts.items())),
                    default_prompt_name=settings.default_prompt_name, text_only=settings.text_only)
    if settings.backend == "sentence_transformers":
        identity.update(batch_size=settings.batch_size, dtype=settings.dtype, autocast=settings.autocast,

    return identity

    matchminer_ai.matching.retrieval ¶

    Exact similarity search in query batches over one or more devices, with a stable top-k.

    For normalized embeddings, score_batches yields cosine similarities of consecutive query batches against every document, in query order. Each device holds a copy of the documents and scores whole batches, so the scores do not depend on how many devices share the work. stable_top_k breaks ties by document index (training's mining has always selected this way). Selection policies on top of the scores (which documents a query may see, lexical or random extras) belong to the caller.

    def score_batches(queries, documents, *, batch_size: int = 128,
                  devices: Sequence[str] = ("cpu",)) -> Iterator[tuple[int, np.ndarray]]:
    """Yield ``(start, scores)`` for query rows ``start:start + batch_size``: float32 ``queries @ documents.T``.

    Batches are spread over ``devices`` (for example ``("cuda:0", "cuda:1")``); a few run ahead of the
    consumer per device.
    """
    import torch

    if batch_size < 1 or not devices:
        raise ValueError("score_batches needs a positive batch size and at least one device")
    queries = np.asarray(queries, dtype=np.float32)
    documents = np.asarray(documents, dtype=np.float32)
    on = {device: torch.as_tensor(documents, device=device) for device in dict.fromkeys(devices)}
    starts = list(range(0, len(queries), batch_size))

    def score(number):
        device = devices[number % len(devices)]
        start = starts[number]
        q = torch.as_tensor(queries[start:start + batch_size], device=device)
        return start, (q @ on[device].T).cpu().numpy()

    window = 2 * len(devices)
    with ThreadPoolExecutor(max_workers=len(devices)) as pool:
        running = [pool.submit(score, number) for number in range(min(window, len(starts)))]
        for number in range(len(starts)):
            yield running[number].result()
            running[number] = None  # release the batch once yielded
            if number + window < len(starts):
                running.append(pool.submit(score, number + window))

    def stable_top_k(scores, k: int) -> list[int]:
