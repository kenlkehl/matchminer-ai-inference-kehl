    Teacher Labeling¶

    matchminer_ai.labeling produces resumable teacher labels of patient-cohort pairs for training TrialSpace and the decision model. It moved here from the training repository on 2026-11-06, unchanged in behaviour: label directories written before the move keep resuming, because the label contracts hash to the same values. The training repository's trialspace_label.py stage calls it.

    Three tasks (matchminer_ai.labeling.tasks):

    • match: the five match labels of a pair in one request (match_quality.labels.system.txt on the patient's key summary section and the cohort's key criteria), decoded under the match JSON schema and scored 0-6 into a resumable score journal;
    • boilerplate: whether the patient clearly fails the cohort's boilerplate criteria (llm_exclusion_criteria.user.txt, ending in Yes! or No!);
    • criteria: one request per tagged criteria line of a pair (criterion_check.labels.user.txt), decoded under its schema; yes means the patient does not clearly fail the line.

    Requests go through the adaptive teacher pool (matchminer_ai.llm.teacher_pool): prompts rendered on the client with the teacher's chat template and sent to /v1/completions on a live server registry, with per-server concurrency that follows vLLM's /metrics. Every answer is kept with its reasoning and complete prompt (responses/); labels.jsonl is the flattened export and, for match, scores.jsonl with scores_ready.json the complete training scores. The prompts carry patient text to the configured servers: use synthetic or authorized data and endpoints only.

    matchminer_ai.labeling.runner ¶

    Resumable teacher labels using the existing adaptive vLLM pool.

    Task match (the default): one request per pair answers the five match labels on the patient's key section and the cohort's key criteria, and each pair's 0-6 score is committed to the score journal. Task boilerplate: one request per pair whose cohort has boilerplate criteria decides whether the patient clearly fails them, from the patient's boilerplate section. Task criteria: one request per candidate line (training builds them: trialspace/candidates.py) answers whether the patient clearly fails that criteria line, from the complete summary and the cohort's numbered criteria (yes = does not clearly fail it). Every response is kept with its reasoning and complete prompt.

    def add_label_cli_args(parser):
    """The labeler's command-line flags, with the teacher pool's (as training's label stage passes them)."""
    from matchminer_ai.llm.teacher_pool import add_remote_cli_args
    add_remote_cli_args(parser)
    parser.add_argument('--corpus', required=True)
    parser.add_argument('--candidates', required=True)
    parser.add_argument('--output', required=True)
    parser.add_argument('--task', choices=list(TASKS), default='match',
                        help='match: the five match labels in one request per pair, scored 0-6 into scores.jsonl; '
                             'boilerplate: whether the patient clearly fails the cohort\'s boilerplate criteria; '
                             'criteria: one request per criteria line of sampled pairs (yes = does not clearly fail it)')
    parser.add_argument('--teacher-model', required=True, help='Served model ID')
    parser.add_argument('--teacher-served-model', help='Endpoint model name when different from the recorded teacher identity; advertised root is verified')
    parser.add_argument('--teacher-tokenizer', required=True, help='Underlying model for tokenizer and vendor sampling')
    parser.add_argument('--cache-dir')
    parser.add_argument('--max-tokens', type=int, default=32768)
    parser.add_argument('--teacher-context', type=int, default=250000)
    parser.add_argument('--pending-requests', type=int, default=0,
                        help='Pairs in flight; 0 automatically follows live endpoint capacity')
    parser.add_argument('--max-auto-pending-requests', type=int, default=DEFAULT_AUTO_WORKERS_MAX,
                        help='Upper bound on automatic pair workers; explicit --pending-requests overrides it')
    parser.add_argument('--label-client-processes', type=int, default=1,
                        help='Client processes sharing the pending pairs, each with its own event loop, and together '
                             'each server\'s concurrency limit; no output or identity depends on it, so a run '
                             'resumes with any value')
    parser.set_defaults(max_concurrent_per_server=DEFAULT_CEILING, initial_concurrent_per_server=DEFAULT_INITIAL,
                        scheduler_adaptive_concurrency=True, request_timeout=7200, max_attempts=4)
    return parser

    def questions(pairs, patients, cohorts, *, task='match', sources=None):
    """One item per pair: key texts for ``match``; boilerplate texts for ``boilerplate``, whose
    pairs without cohort boilerplate criteria have nothing to judge and are skipped."""
    patients = patients if isinstance(patients, dict) else {r['id']: r for r in patients}
    cohorts = cohorts if isinstance(cohorts, dict) else {r['id']: r for r in cohorts}
    if task == 'criteria':
        yield from _criteria_questions(pairs, patients, cohorts, sources)
        return
    field = 'text' if task == 'match' else 'boilerplate'
    seen = set()
    for pair in pairs:
        p, c = patients[pair['patient_id']], cohorts[pair['cohort_id']]
        if p['split'] != c['split'] or pair['split'] != p['split']:
            raise ValueError('Teacher pairs must stay within their corpus split')
        if task == 'boilerplate' and not (c.get(field) or '').strip():
            continue
        item = {**pair, 'task': task}
        key = label_key(item)
        if key in seen:
            continue
        seen.add(key)
        yield {**item, 'key': key, 'messages': judge_messages(task, p.get(field) or '', c[field], sources=sources)}

    matchminer_ai.labeling.tasks ¶

    The teacher's label contracts (moved from the training repository's trialspace/contracts.py, 2026-11-06).

    • match: the five match labels of a patient–cohort pair (reasonableness and the cancer type, burden, treatment history and biomarker specificity answers), asked in ONE prompt per pair (matchminer_ai.matching.match_labels; user instruction 2026-11-04). The patient text is the summary's key section and the cohort text its key criteria. TrialSpace and the decision model's five match questions train on these labels.
    • boilerplate: whether the patient clearly fails any of the cohort's boilerplate criteria, from the summary's boilerplate section (llm_exclusion_criteria.user.txt, the prompt of exclusion_criteria_check_with_llm). The decision model's boilerplate question trains on these labels, inverted: its yes means potentially eligible (not excluded).
    • criteria: one request per criteria line of a sampled pair (criterion_check.labels.user.txt around the decision model's own per-criterion state and question, matchminer_ai.matching.decision_model): the complete patient summary, the cohort's complete numbered criteria and the line restated with its inclusion/exclusion type. The answer is the decision model's target: yes = the patient does not clearly fail the line; no = an inclusion line clearly not met or an exclusion line clearly met, with the criterion_status of the line as it binds the patient (since 2026-11-13 a line judged in its role: an alternative, a requirement for only some patients or a branch that does not bind this patient is not_applicable).

    def contract_hash(task='match', sources=None):
    sources = prompt_sources() if sources is None else sources
    if task == 'match':  # decoded under its JSON schema since 2026-11-05 (user instruction)
        detail = dict(match_labels_contract(), structured=MATCH_LABELS_JSON_SCHEMA)
    elif task == 'boilerplate':
        detail = dict(prompt=BOILERPLATE_PROMPT, answer='Yes!/No!')
    else:  # the per-criterion request is built from the decision model's state and question texts
        detail = dict(prompt=CRITERIA_PROMPT, answer='answer/criterion_status/reason', builder=questions_digest(),
                      structured=CRITERION_LABEL_JSON_SCHEMA)
    # match and boilerplate hash the two prompts they always hashed; criteria hashes its own
    names = (CRITERIA_PROMPT,) if task == 'criteria' else (MATCH_LABELS_PROMPT, BOILERPLATE_PROMPT)
    sources = {name: sources[name] for name in names}
    return hashlib.sha256(json.dumps(dict(version=VERSION, task=task, detail=detail, prompts=sources),
                                     sort_keys=True).encode()).hexdigest()

    def judge_messages(task, patient, cohort, *, sources=None, number=None):
    """Messages for one pair: key texts for ``match``, boilerplate texts for ``boilerplate``; for
    ``criteria``, the complete patient summary, the cohort's tagged items and the line ``number``."""
    sources = prompt_sources() if sources is None else sources
    if task == 'criteria':
        return criterion_teacher_messages(patient, cohort, number)
    if task == 'match':
        return build_match_label_messages(patient, cohort, sources[MATCH_LABELS_PROMPT])
    if task == 'boilerplate':
        return [dict(role='system', content=''),
                dict(role='user', content=sources[BOILERPLATE_PROMPT].format(
                    patient_boilerplate=patient, trial_boilerplate=cohort))]
    raise ValueError('Unknown task')

    def parse_judgment(task, answer, criterion_type=None):
    if task == 'match':
        return dict(labels=parse_match_labels(answer))
    if task == 'boilerplate':
        return parse_boilerplate(answer)
    if task == 'criteria':  # yes = does not clearly fail the line; no = clearly fails it
        return dict(criterion=parse_criterion_label(answer, criterion_type))
    raise ValueError('Unknown task')
