    Match Quality¶

    The decision model's match questions (score_match_quality) and their LLM alternative (score_match_quality_with_llm) read key text only: the patient summary's key section and the cohort's key criteria. Boilerplate is the exclusion-criteria stage's. Each row is one candidate pair with:

    • patient_id;
    • cohort_trial_id (or historical space_trial_id);
    • cancer_history_summary, the patient's key section (or a complete patient_summary, whose text before Other relevant history: is taken);
    • cohort_key_criteria (else cohort_eligibility_criteria when the boilerplate step did not run, else historical clinical_space_summary).

    Match labels¶

    One LLM prompt, match_quality.labels.system.txt (matchminer_ai.matching.match_labels, schema trial-match-labels-v1), asks five yes/no questions about one patient's key section and one cohort's key criteria. Each answer carries an evidence_status (supported, contradicted, insufficient_information or not_applicable) and a reason.

    Label Question Points
    reasonableness No clear evidence that the patient fails any of the key criteria. Missing information is not a mismatch. 1 (gate)
    cancer_type The cohort specifically names a cancer type or histology matching the patient's active cancer. 1
    burden A specific stage or disease-burden requirement is documented as satisfied. 1
    treatment_history A specific prior-treatment requirement is documented as satisfied. 1
    biomarker A specific required biomarker condition is documented as satisfied. 2

    match_score gives 0–6: 0 unless the patient is reasonable, otherwise 1 plus the points of each other yes answer. The training teacher labels pairs with this same prompt and contract, and the decision model learns one yes/no question per label. score_match_quality_with_llm uses it by default (llm_match_quality.prompt_file) and returns llm_match_quality_score (0–6, or -1 when the answer fails the contract) plus one boolean llm_<label> column per label (None when unparsed). Debug mode adds the answer, reasoning and parse status.

    Decision-model scores¶

    score_match_quality asks the decision model (matchminer_ai.matching.decision_model; the decision_model configuration section, base LiquidAI/d1-2B by default) the five match questions about one state: the patient's key section and the cohort's key criteria. Each question's instructions are its section of match_quality.labels.system.txt (without the teacher's evidence-status bookkeeping), except reasonableness, which opens: Is this patient potentially eligible for this cohort after review of the patient history and these key criteria? If the patient is potentially eligible, answer yes; if the patient is clearly ineligible, answer no. It returns each P(yes) as match_quality_<label> and

    match_quality_score = P(reasonable) × (1 + P(cancer_type) + P(burden)
                      + P(treatment_history) + 2·P(biomarker)) / 6

    the expected match score as a fraction of 6, used for ranking. match_quality_pass is match_quality_reasonableness >= match_quality.reasonableness_cutoff (0.5 by default), the decision model's own potentially-eligible answer (since 2026-11-17; before, a match_quality_score cutoff of 0.2 approximated it).

    interpret_match_quality attributes one match question's decision (head, default "reasonableness"): gradient times input embedding for the question's yes-minus-no logit at its answer slot, read in the same packed sequence as the scores. Token offsets refer to the cohort_key_criteria and patient_key_summary sources. Attributions are local model sensitivities for debugging and human review, not clinical rationales.

    Scores and labels are ranking and screening signals, not eligibility determinations. The LLM check sends patient key text to the configured LLM endpoint; use only an endpoint authorized for that data.

    Decision model¶

    matchminer_ai.matching.decision_model ¶

    The decision model: one System One model (LiquidAI d1) answering seven yes/no question families.

    A decision model reads a state and named questions and returns, for each noul (yes/no) question, P(yes) from one forward pass, without generating text. The pinned base model is LiquidAI/d1-2B; the training repository fine-tunes it on the teacher's labels of the same seven families (train_decision_model.py), and decision_model.model_name in the configuration selects either.

    The seven families, and what yes means for each:

    1-5. reasonableness, cancer_type, burden, treatment_history, biomarker: the match labels of :mod:matchminer_ai.matching.match_labels, five questions about one state, the patient summary's key section (cancer history) and the cohort's key criteria (:func:match_state, :func:match_questions). reasonableness yes: the patient is potentially eligible after review of these texts; no: clearly ineligible. The other four yes: the cohort specifically requires that dimension and the patient documentedly satisfies it. 6. boilerplate: one question about the patient summary's boilerplate section and the cohort's boilerplate criteria (:func:boilerplate_state, :func:boilerplate_question). Yes: potentially eligible; no: clearly fails at least one boilerplate criterion. 7. criterion: one question per line of the cohort's eligibility criteria, about the complete patient summary and the cohort's complete numbered criteria (:func:criteria_state, :func:criterion_question; the question restates the line with its number and its inclusion/exclusion type). Yes: the patient does not clearly fail this line (it is met, or its information is missing, or the patient could meet it by waiting, or it does not bind this patient). No: the patient clearly fails it: an inclusion line clearly not met, or an exclusion line clearly met. A line is judged in its role in the criteria (the state states the rules, 2026-11-13): an alternative fails only when the patient clearly fails every alternative of its group, and then all of them fail; an introducing line fails as its lines fail together; a requirement for only some of the patients the criteria admit fails only when it clearly applies; branches that together define who may enroll fail a patient who fits none; and a standalone requirement fails a patient who lacks what it requires.

    These builders are the only definition of the states and questions: the training repository renders its training examples with them, so inference reads exactly what the model learned. Patient text reaches only the configured decision model, which runs locally by default.

    def run_decisions(
    requests: Sequence[tuple[str, Mapping[str, str]]],
    *,
    config: Any = None,
    progress: Callable[[int, int], None] | None = None,
) -> tuple[list[dict[str, float]], dict[str, Any]]:
    """P(yes) of each named question of each ``(state, {name: instructions})`` request.

    Every question is a ``noul`` question; a request's questions are read together after its state
    (``decision_model.set_size`` at a time, the model's trained size by default). Requests longer
    than ``decision_model.max_length`` tokens (the fine-tuning length) still run, with no
    truncation, and are counted in the metadata's ``over_max_length``.
    """
    settings = decision_settings(config)
    model = load_decision_model(settings)
    prompt = d1_module(model, "prompt")
    answers: list[dict[str, float]] = []
    over, tokens = 0, 0
    batch = max(1, int(settings["batch_size"]))
    for start in range(0, len(requests), batch):
        chunk = requests[start:start + batch]
        calls = [(state, {name: noul(text) for name, text in questions.items()}) for state, questions in chunk]
        for state, questions in calls:
            if model.engine.tokens(state, [prompt.as_question(q) for q in questions.values()]) > settings["max_length"]:
                over += 1
        for out in model.system_one_batch(calls, set_size=settings["set_size"]):
            answers.append({name: float(answer["noul"]) for name, answer in out["answers"].items()})
            tokens += int(out["usage"]["input_tokens"])
        if progress is not None:
            progress(min(start + batch, len(requests)), len(requests))
    local = Path(str(settings["model_name"])).expanduser().is_dir()
    metadata = {"model_name": str(settings["model_name"]), "revision": None if local else settings.get("revision"),
                "model_sha": _model_sha(settings), "backend": settings["backend"], "questions_sha256": questions_digest(),
                "set_size": settings["set_size"] or getattr(model.config, "d1_set_size", None),
                "max_length": settings["max_length"], "requests": len(requests),
                "questions": sum(len(q) for _, q in requests), "input_tokens": tokens, "over_max_length": over}
    return answers, metadata

    def score_match_quality(
    candidate_pairs: pd.DataFrame,
    *,
    config: MMAIConfig | None = None,
    filter_low_quality: bool = True,
    return_metadata: bool = False,
) -> pd.DataFrame | tuple[pd.DataFrame, dict]:
    """
    Evaluate the clinical match quality of each candidate patient–cohort pair with the decision model.

    The decision model (:mod:`matchminer_ai.matching.decision_model`, configured by
    ``decision_model``) answers the five match questions about one state: the cohort's key criteria
    and the patient summary's key section (:func:`exclusion_criteria_check` handles the boilerplate).
    The questions are the match labels of :mod:`matchminer_ai.matching.match_labels`:
    ``reasonableness`` (yes: potentially eligible after review of these texts; no: clearly
    ineligible) and the cancer type, burden, treatment history and biomarker specificity answers.

    Parameters
    ----------
    candidate_pairs : pd.DataFrame
        DataFrame of candidate patient–cohort pairs.

        Expected columns
        ----------------
        patient_id : str
            Patient identifier.
        cohort_trial_id : str
            Cohort identifier (historical ``space_trial_id`` is accepted).
        cancer_history_summary : str
            The patient summary's key section (or a complete ``patient_summary``, whose key
            section is taken).
        cohort_key_criteria : str
            The cohort's key criteria (else ``cohort_eligibility_criteria``, else historical
            ``clinical_space_summary``).

    config : MMAIConfig, optional
        MMAI configuration: ``decision_model`` (the model) and ``match_quality.reasonableness_cutoff``.
        Uses default preset when omitted.
    filter_low_quality : bool, default True
        If True, only return rows where ``match_quality_pass`` evaluates to True.
    return_metadata : bool, default False
        When True, also return a metadata dict containing the config snapshot
        and model metadata for this run.

    Returns
    -------
    pd.DataFrame
        Derived output table containing:

        Columns
        -------
        patient_id : str
            Patient identifier.
        cohort_trial_id or space_trial_id : str
            The input's trial identifier.
        match_quality_score : float
            0–1 match score, the expected match score fraction: P(reasonable) × (1 +
            P(cancer type) + P(burden) + P(treatment history) + 2 P(biomarker)) / 6.
        match_quality_pass : bool
            Whether P(reasonable) (``match_quality_reasonableness``) meets
            ``match_quality.reasonableness_cutoff`` (0.5 by default): the decision model's own
            potentially-eligible call. ``match_quality_score`` is for ranking only.
        match_quality_<label> : float
            Each match question's P(yes), for reasonableness, cancer_type, burden,
            treatment_history and biomarker.
    tuple[pd.DataFrame, dict]
        When return_metadata is True, returns the DataFrame plus a metadata dict.
    """
    trial_id, _, _ = _pair_inputs(candidate_pairs)
    resolved_config = config or load_default_preset()
    cutoff = reasonableness_cutoff(resolved_config)
    answers, model_metadata = _decide(candidate_pairs, resolved_config)

    # Convert the answers into a compact, derived result table.
    output = candidate_pairs[["patient_id", trial_id]].copy()
    confidence_scores, heads = _scores(answers)
    output["match_quality_score"] = confidence_scores
    output["match_quality_pass"] = [p >= cutoff for p in heads["reasonableness"]]
    for label, values in heads.items():
        output[f"match_quality_{label}"] = values

    # Optionally keep only matches that pass the quality threshold.
    if filter_low_quality:
        keep_rows = output["match_quality_pass"]
        output = output.loc[keep_rows].copy()
    output = output.reset_index(drop=True)

    # Optionally return metadata for reproducibility/debugging.
    if return_metadata:
        metadata_payload = {
            "package": package_metadata(),
            "config_snapshot": config_snapshot(resolved_config),
            "model_metadata": {
                "score_match_quality": model_metadata,
            },
        }
        return output, metadata_payload
    return output

    def interpret_match_quality(
    candidate_pairs: pd.DataFrame,
    *,
    config: MMAIConfig | None = None,
    top_k: int | None = 30,
    head: str = "reasonableness",
    return_metadata: bool = False,
) -> pd.DataFrame | tuple[pd.DataFrame, dict]:
    """Interpret one match question's decision for specific pairs with token attributions.

    Scores each pair as :func:`score_match_quality` does, then, for the match question ``head``
    (default ``reasonableness``), runs one gradient-enabled forward pass per pair over the same
    packed sequence: gradient times input embedding for the question's yes-minus-no logit at its
    answer slot. Token offsets are relative to the cohort key criteria (``cohort_key_criteria``
    source) and the patient key section (``patient_key_summary`` source). Positive normalized scores
    support the interpreted decision (``head`` yes when P(yes) >= 0.5, else no); negative scores
    oppose it.

    Parameters
    ----------
    candidate_pairs : pd.DataFrame
        One or more specific pairs with the same required input columns as
        :func:`score_match_quality`.
    config : MMAIConfig, optional
        Configuration. Uses the default preset when omitted.
    top_k : int or None, default 30
        Retain the most important tokens per source field. Use ``None`` to
        return every retained input token.
    head : str, default "reasonableness"
        The match question to interpret.
    return_metadata : bool, default False
        Return the config snapshot and model metadata with the result.

    Returns
    -------
    pd.DataFrame
        One row per input pair with the scores, ``token_attributions``, input
        ``attribution_coverage``, and caveat.
    tuple[pd.DataFrame, dict]
        Result and reproducibility metadata when ``return_metadata`` is True.
    """
    from .match_labels import LABELS
    if head not in LABELS:
        raise ValueError(f"head must be one of {list(LABELS)}")
    trial_id, cohorts, patients = _pair_inputs(candidate_pairs)
    resolved_config = config or load_default_preset()
    cutoff = reasonableness_cutoff(resolved_config)
    answers, model_metadata = _decide(candidate_pairs, resolved_config)
    confidence_scores, heads = _scores(answers)
    questions = match_questions()
    explanations, targets = [], []
    for cohort, patient, probability in zip(cohorts, patients, heads[head], strict=True):
        state, ranges = match_state_with_ranges(patient, cohort)
        ranges = {"cohort_key_criteria": ranges["cohort_key_criteria"], "patient_key_summary": ranges["patient_key_summary"]}
        decision = probability >= 0.5
        explanations.append(oriented(attribute_decision(state, questions, head, ranges, config=resolved_config,
                                                        top_k=top_k), decision))
        targets.append(f"{head}_{'yes' if decision else 'no'}")

    output = candidate_pairs[["patient_id", trial_id]].copy()
    output["match_quality_score"] = confidence_scores
    output["match_quality_pass"] = [p >= cutoff for p in heads["reasonableness"]]
    for label, values in heads.items():
        output[f"match_quality_{label}"] = values
    output["attribution_method"] = [item["method"] for item in explanations]
    output["attribution_target"] = targets
    output["token_attributions"] = [item["token_attributions"] for item in explanations]
    output["attribution_coverage"] = [item["coverage"] for item in explanations]
    output["attribution_caveat"] = TOKEN_ATTRIBUTION_CAVEAT
    output = output.reset_index(drop=True)

    if return_metadata:
        return output, {
            "config_snapshot": config_snapshot(resolved_config),
            "model_metadata": {"interpret_match_quality": model_metadata},
            "interpretability": {"method": "gradient_x_input", "top_k_per_source": top_k, "head": head},
        }
    return output

    Parameters

    candidate_pairs : pd.DataFrame
        One row per candidate pair: ``patient_id``; ``cohort_trial_id`` (or historical
        ``space_trial_id``); the patient's key section, ``cancer_history_summary`` (or a complete
        ``patient_summary``, whose key section is taken); and the cohort's key criteria,
        ``cohort_key_criteria`` (else ``cohort_eligibility_criteria``, else ``clinical_space_summary``).

    Returns
    -------
    pd.DataFrame
        ``patient_id``, the trial identifier, ``llm_match_quality_score`` (0–6 from

        contract) and one boolean ``llm_<label>`` column per label (None when unparsed). With
        debug_mode: ``llm_match_quality_answer_text``, ``llm_match_quality_reasoning_text`` and
        ``llm_match_quality_parse_status`` (``parsed`` or the validation error).
    tuple[pd.DataFrame, dict]
        When return_metadata is True, returns the DataFrame plus metadata.
    """
    from matchminer_ai._texts import patient_key_texts, trial_id_column, trial_key_texts
    from .match_labels import LABELS, build_match_label_messages, match_score, parse_match_labels

    if "patient_id" not in candidate_pairs.columns:
        raise ValueError("candidate_pairs is missing required columns: patient_id")
    trial_id = trial_id_column(candidate_pairs)
    patients, cohorts = patient_key_texts(candidate_pairs), trial_key_texts(candidate_pairs)

    resolved_config = config or load_default_preset()
    llm_config = dict(resolved_config.llm_match_quality)
    prompt = _load_prompt_template(str(llm_config["prompt_file"]).strip())
    messages_list = [build_match_label_messages(patient, cohort, prompt) for patient, cohort in zip(patients, cohorts)]

            },

    matchminer_ai.matching.match_labels ¶

    The five match labels of a patient–cohort pair, asked in one prompt.

    match_quality.labels.system.txt asks one LLM request for five yes/no answers about one patient's key summary section and one cohort's key criteria:

    • reasonableness: no clear evidence that the patient fails any of the key criteria;
    • cancer_type, burden, treatment_history, biomarker: whether the cohort specifically requires that dimension and the patient documentedly satisfies it.

    Every answer carries an evidence_status and a reason. The training teacher labels pairs with this contract, the decision model learns one yes/no question per label, and score_match_quality_with_llm uses the same prompt. :func:match_score combines the answers into the 0–6 match score: 0 unless reasonable, else 1 plus 1 each for cancer type, burden and treatment history and 2 for biomarker.

    def match_score(answers: dict[str, Any]) -> int:
    """0–6: 0 unless reasonable, else the points of every yes answer.

    ``answers`` maps each label to "yes"/"no", a bool, or a parsed answer object.
    """
    def yes(label):
        value = answers[label]
        value = value["answer"] if isinstance(value, dict) else value
        return value is True or value == "yes"
    if not yes("reasonableness"):
        return 0
    return sum(points for label, points in POINTS.items() if yes(label))

    def parse_match_labels(text: str, finish_reason: str = "stop") -> dict[str, dict[str, str]]:
    """The five answers; any deviation from the contract raises ValueError."""
    from matchminer_ai.trials.cohort_schema import _unique_keys, unwrap_json_fence
    if finish_reason != "stop":
        raise ValueError(f"Incomplete response: {finish_reason}")
    try:
        result = json.loads(unwrap_json_fence(text.strip()), object_pairs_hook=_unique_keys)
    except (TypeError, ValueError) as exc:
        raise ValueError(f"Response must be valid JSON: {exc}") from exc
    if not isinstance(result, dict) or set(result) != set(LABELS):
        raise ValueError(f"Response must be a JSON object with exactly the fields {list(LABELS)}")
    for label in LABELS:
        value = result[label]
        if not isinstance(value, dict) or set(value) != {"answer", "evidence_status", "reason"}:
            raise ValueError(f"{label} must have exactly answer, evidence_status and reason")
        if value["answer"] not in ("yes", "no"):
            raise ValueError(f"{label}.answer must be yes or no")
        if value["evidence_status"] not in EVIDENCE_STATUSES:
            raise ValueError(f"{label}.evidence_status must be one of {list(EVIDENCE_STATUSES)}")
        if not isinstance(value["reason"], str) or not value["reason"].strip():
            raise ValueError(f"{label}.reason must be a nonempty explanation")
    return {label: result[label] for label in LABELS}
