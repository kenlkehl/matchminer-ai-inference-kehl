    Patients¶

    summarize_patients turns each patient's longitudinal notes into one cancer-history summary, which TrialSpace and the decision model compare with cohorts (How matching works). The same module has helpers for patient PDFs, note compression and workup documentation review. Structured, evidence-linked records from the same notes are described in Structured Clinical Extraction.

    Serial summarization¶

    import pandas as pd
from matchminer_ai import load_preset
from matchminer_ai.patients import summarize_patients

config = load_preset("default")
notes = pd.DataFrame([
    {"patient_id": "P001", "note_date": "2025-01-05", "note_text": "Fabricated note text ..."},
    {"patient_id": "P001", "note_date": "2025-03-12", "note_text": "Fabricated note text ..."},
])
patients, qc = summarize_patients(notes, config=config, checkpoint_dir="runs/patients", return_qc=True)

    The input has one row per note with patient_id, note_text and note_date. Each patient's record is prepared, then summarized chunk by chunk:

    1. Order: notes are sorted by date, undated notes last; notes without text are dropped.
    2. Repeated sentences: a sentence repeated across the patient's notes is kept only where it first appears.
    3. Chunks: the notes are joined under === Clinical Note dated <date> === headers and split into overlapping token chunks (patient.chunk_size 50,000 and patient.chunk_overlap 500, counted with the patient model's tokenizer).
    4. Updates: each chunk's prompt (patient.serial.user.primer.txt) carries the summary accepted for the previous chunk, and its answer becomes the summary the next chunk updates.
    5. Sections: the final summary is split into its key and boilerplate sections.

    The notes reach the configured LLM endpoint, so use only an endpoint authorized for them.

    Output¶

    One row per patient:

    Column Content Read by
    patient_id The patient.
    last_note_date Date (YYYY-MM-DD) of the latest dated note the summary includes. Updates
    patient_summary The complete summary. The per-criterion check, serial updates, summary-quality checks
    cancer_history_summary The key section: the text before Other relevant history:. TrialSpace retrieval, the decision model's match questions
    general_exclusion_criteria_evidence The boilerplate section: the text after that heading (Not documented. when absent). The decision model's boilerplate question

    The complete summary holds the cancer-history fields (age, sex, cancer type, histology, current extent, biomarkers, treatment history; one block per active cancer) and ends with the boilerplate section:

    Other relevant history:
ECOG 1. Chronic kidney disease. Remote inactive prostate cancer.
    • Treatment history lists anti-cancer treatment only, one line per regimen (dates, agents, cycles, best response). Each update carries every earlier regimen forward.
    • Other relevant history records, with dates, the evidence for the general criteria most trials share: performance status, measurable disease, brain and other CNS metastases and their treatment, the most recent routine labs (blood counts, coagulation, kidney and liver function), ejection fraction and QTc, toxicities of earlier cancer treatment, conditions other than cancer (including transplants and drug allergies), recent major surgery other than cancer surgery, other and inactive cancers, participation in any clinical trial, and hospice enrollment or a decision to stop anti-cancer therapy.
    • Left out: a patient whose summary is empty or starts with "No information", or still fails the quality checks, has no row. The QC report (return_qc=True) counts them (patients_dropped_noninformative_summary, patients_failed_inference); see QC metrics.
    • Debug columns: with debug_mode, patient_answer_text and patient_reasoning_text (the last chunk's answer and reasoning) and patient_summary_attempts (every attempt's trace).
    • Metadata: return_metadata=True adds the package version, config snapshot and model metadata.

    A Boilerplate: heading in a summary is read as Other relevant history:. embed_for_matching, the decision-model checks and their LLM versions also accept a complete patient_summary in place of a section column and take the section they need. patients.postprocess.split_patient_summary returns the two sections of one text, and add_summary_sections adds both columns to a table with patient_summary.

    Summary quality checks¶

    patients.check_patient_summary(text) runs read-only checks on one summary. It looks for:

    • self-editing language ("I should", "Wait,");
    • prompt or formatting commentary;
    • raw reasoning delimiters;
    • repeated cancer-field values;
    • repeated long prose.

    It returns versioned findings with character offsets, line numbers and a high or review confidence. The diagnostics contain no patient text. These are review signals, not clinical validation, and the checker never rewrites a summary.

    • Multiple primary cancers and repeated headings are allowed.
    • Matching age, cancer type, histology and biomarkers alone asks for review.
    • Matching extent and treatment history as well identifies a repeated cancer section.

    summarize_patients(..., return_qc=True) adds aggregate flags to its QC report (patients_summary_quality_flagged, overall and per finding).

    Serial summarization checks each chunk's answer before it becomes the next chunk's prior summary.

    • Regenerated: every finding except matching core cancer fields (drafting or commentary text, reasoning delimiters, repeated sections or prose), plus empty output and incomplete completions. The chunk is regenerated from the original notes and the last accepted prior summary, up to patient.summary_quality_max_attempts (3) attempts.
    • Not regenerated: matching only the core cancer fields, which stays a review signal.
    • Trace: patient.summary_quality_trace_dir keeps every prompt, answer and reasoning trace in a local directory, rejected attempts included. Debug output includes patient_summary_attempts, and the metadata (return_metadata=True) reports attempt and rejection counts (summary_quality).

    Updating existing summaries¶

    Pass earlier summaries as existing_summaries, together with the patients' notes, to continue each summary instead of starting over. Each patient's first new chunk is summarized onto the existing summary.

    The summary can be given in any of these layouts; the first one present is used:

    • patient_summary_with_boilerplate: a complete summary;
    • cancer_history_summary and general_exclusion_criteria_evidence: this function's own output, so a result can be passed back with new notes;
    • patient_summary and patient_boilerplate_text: the training pipeline's output;
    • patient_summary alone: a complete summary.

    last_note_date (optional) is the date of the last note an existing summary includes. Every output row has it, so the output can be passed straight back.

    • When it is given (it must be readable on every row), only notes dated after it are summarized onto the summary. Undated notes can't be placed after it and are left out.
    • When that last note is within 10 days of today (RECENT_SUMMARY_LOOKBACK_DAYS), notes from 10 days before it are summarized again, so notes that arrive late with earlier dates are not missed.
    • Without last_note_date, every supplied note is summarized onto the summary, so pass only new notes.

    A patient with no new usable notes keeps their existing summary unchanged. It is normalized, but never dropped as non-informative.

    first = summarize_patients(notes_until_june)
update = summarize_patients(notes_until_july, existing_summaries=first)  # newer notes only

    Scheduling patient summarization¶

    Each patient's chunks are summarized in order, each prompt carrying the summary accepted for that patient's previous chunk. patient.scheduling chooses how patients share the backend:

    • continuous (the default): with a remote backend, each patient's next chunk is sent as soon as the previous one is final (after its quality retries), so the endpoints keep their full request capacity in flight and a long record does not hold back the rest of its batch. Waiting patients start longest remaining chain first. A local engine, which batches prompts itself, runs in rounds instead.
    • rounds: every patient's first chunk is sent as one batch, then every patient's second chunk, and so on; each round waits for its slowest patient.

    Both send the same prompts with the same quality checks and retries, and give the same output rows, metadata and QC counts. See patient.scheduling.

    Resuming patient summarization¶

    Pass a run-specific directory as checkpoint_dir to save progress. Each chunk's result is saved as soon as it is final, so an interrupted run loses only the requests it had in flight. Call summarize_patients again with the same directory to continue each patient from their last saved chunk, under either scheduling. Without checkpoint_dir, nothing is written.

    The directory holds:

    • prepared_chunks.parquet: the patients' note chunks, saved once before the first chunk is summarized;
    • chunk_journal.jsonl: one JSON line per finished (patient, chunk) result, appended and synced to disk as each result is final (a round's results together, under rounds).
    Column Description
    patient_id Patient identifier.
    chunk_index The patient's chunk, counting from 0.
    prior_summary The summary carried into this chunk, before it was incorporated.
    patient_reasoning_text The model's reasoning trace for this chunk.
    patient_answer_text The model's summary output for this chunk.
    finish_reason Generation finish reason, e.g. "stop" or "error".

    On resume, a saved result is used only when it is the patient's next chunk and, after the first chunk, its prior_summary is the summary the patient's saved chain has reached, so every patient continues one consistent chain. A last journal line that an interrupted write left unfinished is skipped and removed. Older directories with one Parquet file per round (round_0000.parquet, ...) resume too.

    "error" marks a patient whose summary still failed after patient.summary_quality_max_attempts attempts; that patient's later chunks are skipped, including after resuming. Checkpoint files contain patient note text and summaries, so store them under the same controls as the input notes.

    Inspecting a run¶

    patients.serial_trace(checkpoint_dir) reads a checkpoint directory the way resuming does and returns one row per prepared chunk, in each patient's chain order: patient_id, chunk_index, first_date, last_date and, where the chunk has a result, prior_summary, reasoning, summary and finish_reason. Nothing is sent to a model.

    PDF patient records¶

    summarize_patients also accepts one local PDF path, or an ordered sequence of PDF paths, for a single patient. Each page uses embedded text when it has enough, otherwise local RapidOCR (as in ocr_pdf). The documents are combined into one long note, which is then summarized like any other record.

    summary = summarize_patients(
    ["record-part-1.pdf", "record-part-2.pdf"],
    patient_id="P001",
    config=config,
)

    To inspect or edit the extracted text first, call the preparation step directly:

    from matchminer_ai.patients import concatenate_patient_note_pdfs

long_note = concatenate_patient_note_pdfs(["record-part-1.pdf", "record-part-2.pdf"])
    • Order and boundaries: documents keep the order given, with numbered boundary markers. Filenames and file timestamps are not copied into the text, and no clinical dates are inferred: the combined note is undated.
    • Accuracy: OCR is probabilistic; compare important content with the original PDFs.
    • Privacy: OCR runs locally, but summarization sends the extracted text to the configured LLM endpoint.

    Note compression¶

    compress_patient_notes rewrites each nonblank note_text row in one independent request to the configured remote patient LLM, and compress_patient_note does the same for one string.

    from matchminer_ai.patients import compress_patient_note, compress_patient_notes

config.remote["enabled"] = True
config.remote["server_urls"] = ["http://localhost:8000/v1"]
config.patient["remote"]["model_name"] = "my-endpoint-model"

compressed = compress_patient_notes(
    notes,
    config=config,
    max_concurrent_requests=8,
    progress_callback=lambda completed, total: print(completed, total),
)
one_note = compress_patient_note("Fabricated note text.", config=config)
    • Input and output: every run of whitespace becomes one space before sending, and only that note's text is sent. The returned copy keeps every input row, column and index unchanged and adds compressed_note_text. Blank strings give "" without a request; null or non-string text and an existing compressed_note_text column are rejected.
    • Prompt: patient.note_compression.system.txt asks for extreme but lossless token density and only the compressed note. Blank, refused, token-limited, malformed and explanatory answers are retried, then raise; a failure never returns a partial table. Oversized notes are rejected, never truncated or split.
    • Endpoint: exactly one remote server URL, so model discovery and token counting describe the server that answers. Requests share the endpoint cap, authentication, sampling, timeout, retries and cancellation; max_concurrent_requests defaults to remote.max_concurrent_requests. Set remote.context_window when the endpoint does not advertise one, and remote.tokenizer_mode = "bytes" for servers without vLLM's /tokenize.
    • Reasoning: thinking="off" (the default) sends chat_template_kwargs.enable_thinking=false without changing the shared configuration. An adapter that cannot disable reasoning keeps its settings, and an endpoint that rejects the switch with HTTP 400 or 422 is retried once without it. thinking="on" opts in. attrs["note_compression"] records thinking_requested and the thinking actually dispatched (off, on, default when no switch was sent, mixed, or not_requested for all-blank input).
    • Privacy: reasoning is discarded, and no notes, prompts or outputs are logged or written to disk.

    Compression is experimental: asking for losslessness does not establish it. Keep the original notes for human review and exact quotations. Summarization and note-search question answering do not use compressed notes.

    Workup documentation review¶

    from matchminer_ai.patients import review_patient_workup

review = review_patient_workup(
    patient_notes,                   # one patient's note DataFrame or concatenated text
    space["diagnostic_workup"],      # a guideline catalog record's workup items
    config=config,                   # patient LLM, remote.enabled=True
    population_context=space["cohort_key_criteria"],  # the guideline population, not patient facts
    progress_callback=print,
)

    This opt-in workflow reviews all of one patient's notes serially, carrying forward a JSON assessment of every workup item. It does not use the patient summary or any retrieval as evidence.

    • Input: a DataFrame with nonempty note_text, optional note_date and note_type, and an optional patient_id with a single value; or a string, which has no date provenance. Dated notes are sorted, undated notes follow them, and repeated sentences are kept so dated evidence and contradictions are not lost.
    • Result: assessments, notice and metadata. Each assessment keeps the original recommendation and its zero-based recommendation_index, plus status (completed, partially_completed, planned, not_done, not_documented, unclear), applicability (applies, not_applicable, uncertain), bottom_line and evidence.
    • Evidence: the model returns only name, status, applicability and bottom_line, never quotes or note numbers. Code attaches every reviewed note fragment verbatim (note_number, one-based in chronological order; note_date; note_type; quote), including irrelevant or conflicting passages. They are review context, not selected citations (metadata.evidence_selection is automatic_reviewed_excerpts), and verbatim provenance does not validate the model's interpretation.
    • Requests: the patient model, sampling and reasoning settings (xhigh by default) on exactly one remote endpoint with /tokenize and an advertised max_model_len, or an explicit patient.context_window (with patient.tokenizer_mode: bytes for servers without /tokenize). The configured output reserve (patient.remote.request_params.max_tokens, 50,000) is kept. Chunks follow patient.chunk_size and chunk_overlap unless overridden, with at most recommendation_batch_size (6) items per request. Oversized prompts split note packets further and never truncate notes.
    • Failures: three bounded attempts reject incomplete, malformed or misaligned findings, and a later chunk's silence cannot erase a documented finding. Errors are not echoed with patient text. Nothing is written to disk, and no reasoning is returned.

    The configured endpoint receives the raw notes and must be authorized for them.

    Backup model. review_patient_workup and review_patient_workup_with_note_search accept backup_config (a separate MMAIConfig with the backup's endpoint, model, sampling and reasoning) and max_consecutive_failures (default 3, from 1 to 10). Nothing changes on the successful path.

    • Full-note review switches once after that many failed attempts on a packet, retries the packet within the backup's context and keeps every validated assessment; the remaining packets use the backup. Metadata reports primary_model, backup_used, backup_events, request attempts and validated_packets.
    • Note-search review restarts only the failed item, in a fresh isolated REPL with the same budget, after repeated Python errors or failed attempts. Follow-up can switch once within its call budget; a failed backup never triggers another switch. Per-item metadata records each switch, the models, the reasons and the combined costs. Backups keep worker isolation, cancellation, output and context reserves, and exact-evidence validation.

    This is a documentation review for human review, not an overall guideline concordance determination. Not documented does not mean not done. Conditional indications, compound items, alternatives, historical tests, timing and conflicting evidence need clinical review. Treatment concordance is not assessed.

    answer_patient_questions, answer_patient_question_batch and review_patient_workup_with_note_search answer questions and review workup items by searching the original notes in an isolated Python REPL instead of reading every chunk. See note-search question answering.

    def check_patient_summary(text: str | None) -> dict:
    """Return versioned, JSON-compatible flags without rewriting the summary.

    ``high`` means strong evidence of malformed output, not clinical certainty.
    ``review`` includes ambiguous first-person prose and repeated core fields:
    two distinct primaries can legitimately share those field values. No flag
    alone establishes that a cancer section can safely be removed.
    """
    if text is None:
        text = ""
    if not isinstance(text, str):
        raise TypeError("Patient summary must be text or None")
    findings = []

    def add(code, confidence, start, end, message, **extra):
        findings.append(dict(code=code, confidence=confidence, start=start, end=end,
                             line=text.count("\n", 0, start) + 1, message=message, **extra))

    if not text.strip() or text.lstrip().startswith("ERROR:"):
        add("empty_or_failed", "high", 0, len(text), "Summary is empty or marked as a generation error.")
    for pattern, code, confidence, message in (
        (_SELF_EDIT, "self_editing_language", "review", "Possible first-person drafting or self-correction."),
        (_COMMENTARY, "prompt_commentary", "high", "Prompt, formatting, or answer-construction commentary."),
        (_REASONING, "reasoning_delimiter", "high", "Raw model or reasoning delimiter in the summary."),
    ):
        for match in pattern.finditer(text):
            add(code, confidence, match.start(), match.end(), message)

    sections = _sections(text)
    core_seen = {}
    full_seen = {}
    for section in sections:
        fields = section["fields"]
        full_signature = tuple(fields.get(k, "") for k in ("age", *_CLINICAL))
        # Whole sections can be copied even when biomarkers are undocumented.
        # Missing headings are different from explicitly documented unknowns.
        complete = all(fields.get(k) for k in _CLINICAL)
        if complete and full_signature in full_seen:
            previous = full_seen[full_signature]
            add("duplicate_cancer_section", "high", section["start"], section["end"],
                "All five cancer fields repeat an earlier section.",
                previous_line=text.count("\n", 0, previous["start"]) + 1,
                fields=list(("age", *_CLINICAL)))
            continue
        if complete:
            full_seen[full_signature] = section
        signature = tuple(fields.get(k, "") for k in _CORE)
        # Missing/unknown fields do not establish duplication.
        if any(v.rstrip(".") in _UNKNOWN for v in signature):
            continue
        previous = core_seen.get(signature)
        if previous is not None:
            add("repeated_cancer_fields", "review", section["start"], section["end"],
                "Age, cancer type, histology and biomarkers repeat; review for distinct primaries before changing anything.",
                previous_line=text.count("\n", 0, previous["start"]) + 1,
                fields=list(_CORE))
        else:
            core_seen[signature] = section

    # Catch repeated long prose even when it has no recognizable field headers.
    paragraphs = defaultdict(list)
    for match in re.finditer(r"\S[^\n]*(?:\n(?![ \t]*\n)[^\n]*)*", text):
        normalized = _normalized(match.group())
        if len(normalized.split()) >= 40 and not _HEADINGS.search(match.group()):
            paragraphs[normalized].append(match)
    for matches in paragraphs.values():
        for match in matches[1:]:
            add("repeated_long_paragraph", "review", match.start(), match.end(),
                "A paragraph of at least 40 words repeats verbatim after whitespace/case normalization.",
                previous_line=text.count("\n", 0, matches[0].start()) + 1)

    findings.sort(key=lambda finding: (finding["start"], finding["code"]))
    return dict(version=SUMMARY_QUALITY_VERSION, flagged=bool(findings),
                cancer_sections=len(sections), findings=findings)

    population_context: str | None = None,
    limits: NoteSearchLimits | None = None,
    max_parallel_questions: int | None = None,
    thinking: str | None = "off",
    search_reasoning_effort: str | None = "low",
    review: WorkupSearchReviewConfig | None = None,
    progress_callback=None,
) -> dict:
    """Search for each workup item in parallel, retaining the workup review schema.

    Supply a notes DataFrame, concatenated text, or both (using history=). The
    DataFrame is authoritative when both exist; note_text is required and
    note_date/note_type are optional. An existing patient_summary guides pandas
    and regex navigation but is never a source of patient-note evidence.

    Uses the configured patient endpoint and sampling profile. Each item has an
    isolated Python REPL and a provisional structured assessment. By default,
    shared search vocabulary and up to two focused evidence reviews follow it;
    unresolved/coverage-limited items can use bounded serial full-record review.
    Pass WorkupSearchReviewConfig(max_review_passes=0) to disable follow-up.
    Thinking is off by default. Pass thinking="on" to enable it or None to inherit
    the configured patient endpoint switch. Providers without an off switch retain
    their supported effort setting. Reasoning traces are never replayed.
    Structured input dates are assigned by code after
    automatic capture of original pandas/search/read excerpts. The model does not emit
    quotes, offsets or citation IDs. Excerpts are reviewed context, not individually
    selected supporting citations. String input has unavailable dates. Per-item failures
    are status ``error``, never missing-documentation findings.
    Defaults to twelve Python cells and sixteen initial request attempts per item,
    including its answer and retries, plus at most twelve follow-up calls per item
    including vocabulary and retries. Up to five items can use full-record fallback, at most eight
    chunks each. Failed follow-up preserves the last validated assessment with an
    explicit limitation and audit status. All items may run concurrently. The configured
    endpoint request cap still applies. Pass explicit limits/concurrency to override.
    The first search-only request uses low effort where supported; subsequent
    assessment/follow-up turns retain the configured effort. Pass None to inherit
    that effort for every request instead.
    An explicit backup_config retries only failed items after repeated Python
    errors or failed request/validation attempts. Each initial attempt gets a
    fresh isolated REPL and the same bounded budget; combined costs are reported.
    Follow-up retains validated findings and can switch once within its existing
    call budget. Backup sampling and reasoning use backup_config independently.
    """
    started = time.monotonic()
    review = review or WorkupSearchReviewConfig()
    if not isinstance(review, WorkupSearchReviewConfig):
        raise TypeError("review must be a WorkupSearchReviewConfig instance.")
    config = config or load_default_preset()
    if not isinstance(config, MMAIConfig):
        raise TypeError("config must be an MMAIConfig instance.")
    if thinking is not None and thinking not in ("on", "off"):
        raise ValueError("thinking must be on, off, or None.")
    if not remote_enabled(config):
        raise ValueError("Workup review requires a configured remote LLM endpoint.")
    backup = WorkupBackup(backup_config, max_consecutive_failures)
    limits = limits or NoteSearchLimits()
    if not isinstance(limits, NoteSearchLimits):
        raise TypeError("limits must be a NoteSearchLimits instance.")
    record = prepare_record(
        history,
        notes,
        patient_summary,
        max_bytes=limits.max_history_bytes,
        max_summary_chars=limits.max_summary_chars,
    )
    source = record.spans
    if not isinstance(recommendations, list) or not recommendations:
        raise ValueError("Supply at least one diagnostic/workup recommendation.")
    if population_context is not None and not isinstance(population_context, str):
        raise TypeError("population_context must be guideline population text or None.")
    for item in recommendations:
        if (
            not isinstance(item, dict)
            or not isinstance(item.get("name"), str)
            or not item["name"].strip()
            or not isinstance(item.get("conditions", ""), str)
        ):
            raise ValueError("Each recommendation requires a name and text conditions.")
    if max_parallel_questions is None:
        max_parallel_questions = len(recommendations)
    if record.structured:
        history, spans = record.history, record.spans
    else:
        history, spans = _history(source)
        record.history, record.spans = history, spans
    questions = [
        json.dumps(
            {
                "task": "Assess documentation and applicability of this workup item.",
                "recommendation": {
                    "name": r["name"],
                    "conditions": r.get("conditions", ""),
                },
                "guideline_population": population_context,
            },
            ensure_ascii=False,
        )
        for r in recommendations
    ]
    progress = progress_callback or (lambda _: None)
    progress(f"Preparing agentic note search for {len(questions)} workup items")
    patient = copy.deepcopy(config.patient)
    if thinking is not None:
        patient.setdefault("local", {}).setdefault("chat_template_kwargs", {})[
            "enable_thinking"
        ] = thinking == "on"
        patient.setdefault("remote", {}).setdefault("extra_body", {}).setdefault(
            "chat_template_kwargs", {}
        )["enable_thinking"] = thinking == "on"
    runtime = build_llm_runtime_config("patient", patient, config=config)
    runtime["max_retries"] = backup.threshold if backup.enabled else 3
    resolved, _ = resolve_structured_config(runtime, cache_dir=None)
    llm = NoteSearchLLMConfig(
        **asdict(resolved),
        sampling_profile=runtime.get("sampling_profile", "auto"),
        reasoning_effort=runtime.get("reasoning_effort", "xhigh"),
        search_reasoning_effort=search_reasoning_effort,
    )

    def resolve_backup(backup_config):
        progress("Primary agent model failed repeatedly; trying the configured backup model")
        runtime = build_llm_runtime_config(
            "patient", backup_config.patient, config=backup_config
        )
        runtime["max_retries"] = 3
        resolved, _ = resolve_structured_config(runtime, cache_dir=None)
        return NoteSearchLLMConfig(
            **asdict(resolved), sampling_profile=runtime.get("sampling_profile", "auto"),
            reasoning_effort=runtime.get("reasoning_effort", "xhigh"),
            search_reasoning_effort=search_reasoning_effort,
        )

    def backup_factory():
        return backup.get(resolve_backup)
    completed = 0

    def on_progress(event):
        nonlocal completed
        completed += 1
        progress(
            f"Agentic note search: {completed}/{len(questions)} workup items finished "
            f"(item {event['question_index'] + 1}: {event['status']})"
        )

    contract = _answer_format(spans, request_review=review.max_review_passes > 0)
    result = _run_question_batch(
        [{"patient_id": "patient", "history": history, "questions": questions}],
        llm=llm,
        limits=limits,
        max_parallel_patients=1,
        max_parallel_questions=max_parallel_questions,
        max_active_questions=max_parallel_questions,
        progress_callback=on_progress,
        answer_format=contract,
        prepared_records=[record],
        backup_llm_factory=backup_factory if backup.enabled else None,
        failure_threshold=backup.threshold,
    )
    answers = result["patients"][0]["answers"]
    if review.max_review_passes:
        progress(
            "Checking search coverage and reviewing provisional workup assessments"
        )
        answers = review_answers(
            answers,
            history=history,
            spans=spans,
            llm=_resolve_llm(llm),
            config=review,
            contract=contract,
            concurrency=max_parallel_questions,
            progress=progress,
            patient_summary=record.patient_summary,
            backup_llm_factory=backup_factory if backup.enabled else None,
            failure_threshold=backup.threshold,
        )
    assessments = []
    for i, (answer, recommendation) in enumerate(
        zip(answers, recommendations, strict=True)
    ):
        finding = answer["answer"]
        if not isinstance(finding, dict):
            finding = {
                "status": "error" if answer["status"] == "error" else "unclear",
                "applicability": "uncertain",
                "bottom_line": finding
                or "The search failed; no documentation finding was made.",
            }
        evidence = []
        for item in answer["evidence"]:
            note = _source_note(item, spans)
            evidence.append(
                {
                    **item,
                    "note_number": note["note_number"],
                    "note_date": note["note_date"],
                }
            )
        assessments.append(
            {
                **finding,
                "name": recommendation["name"],
                "recommendation_index": i,
                "recommendation": copy.deepcopy(recommendation),
                "evidence": evidence,
                "review_status": answer["status"],
                "limitations": answer["limitations"],
                "metadata": answer["metadata"],
            }
        )
    progress(
        "Agentic workup documentation review finished; inspect findings and limitations"
    )
    return {
        "assessments": assessments,
        "notice": result["notice"],
        "metadata": {
            **result["metadata"],
            "method": "agentic",
            "elapsed_seconds": round(time.monotonic() - started, 4),
            "followup_review": asdict(review),
            "incomplete_review_items": sum(
                a["metadata"].get("followup_review", {}).get("status") == "incomplete"
                for a in answers
            ),
            "scope": "searched_excerpts",
            "evidence_selection": "automatic_reviewed_excerpts",
            "note_count": len(source),
            "patient_summary_used": record.patient_summary is not None,
            "patient_summary_role": "navigation_context_only",
            "structured_notes": record.structured,
            "text_supplied": record.text_supplied,
            "input_precedence": "dataframe" if record.structured else "history",
            "requests": sum(a["metadata"]["requests"] for a in answers),
            "failed_items": sum(a["status"] == "error" for a in answers),
            "backup_used": any(a["metadata"].get("backup_used") for a in answers),
            "backup_items": sum(bool(a["metadata"].get("backup_used")) for a in answers),
            "undated_notes": sum(n["note_date"] is None for n in source),
        },
    }

    def add_summary_sections(df: pd.DataFrame, column: str = "patient_summary") -> pd.DataFrame:
    """Add ``cancer_history_summary`` (key) and ``general_exclusion_criteria_evidence``
    (boilerplate) columns split from a complete ``patient_summary`` column."""
    df = df.copy()
    sections = [split_patient_summary(text) for text in df[column].fillna("").astype(str)]
