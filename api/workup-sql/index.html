    SQL-Agent Workup Checks¶

    Review aids, not determinations

    Results say whether structured items extracted from the notes document a guideline workup step. An LLM agent wrote each query and an LLM extracted the items: check every cited quote against its note. Not documented means no extracted item matched, not that the step was not done. This does not establish overall guideline concordance.

    This is a third way to check guideline workup, beside the note-reading reviews and the compiled-query method (Extraction-Based Workup Checks). Like the compiled-query method, it reads the records of Structured Clinical Extraction. The difference is that an LLM agent writes each requirement's check as SQL after looking at the data: which codes are used, how text fields are spelled, how often things occur and how dates look.

    1. Database. build_extraction_database turns extraction records into relational tables: one table per item type, patients, documents, an items view, and vocabulary. write_extraction_database writes them as a DuckDB file.
    2. One query per requirement. For each distinct workup item (name, conditions, category), compile_workup_sql runs a bounded agent over an exploration database, normally a whole extraction store.
    3. Before it starts, code counts what the database holds (the store profile, below) and puts it in the agent's system prompt.
    4. Each turn the agent returns one JSON action: search, query, submit, accept or not_expressible.
    5. A submission must return one row per patient. Code runs it over every exploration patient, checks its output contract and shows the agent the distribution of results with example rows. The agent then accepts it or revises it.
    6. The accepted query is cached.
    7. Run once per cohort. check_workup_with_sql builds the cohort's database from its own records and runs each accepted query once over it. It reports in the shape of check_workup_with_extractions: status, reason, applicability, bottom_line, evidence quotes and limitations. The report's metadata.method is extraction_sql.
    from matchminer_ai import load_default_preset
from matchminer_ai.patients import (
    build_extraction_database, check_workup_with_sql, compile_workup_sql,
    write_extraction_database,
)

config = load_default_preset()
config.remote.update(enabled=True, server_urls=["http://localhost:8000/v1"])
config.workup_sql_agent["remote"]["model_name"] = "served/model"

store = build_extraction_database([document_records, patient_records])
write_extraction_database("store.duckdb", store)            # the exploration database

compiled = compile_workup_sql(
    space["diagnostic_workup"], database="store.duckdb", config=config,
    population_context=space["cohort_key_criteria"], cache=my_cache,
)
report = check_workup_with_sql([cohort_documents, cohort_patients], compiled,
                               patient_ids=cohort_ids)

    For a population, matchminer_ai.population.check_population_workup_with_sql takes a cohort (with its space) and the accepted queries. It links records to the cohort's own notes by note id, as check_population_workup_with_extractions does. The report has method: extraction_sql and one queries entry per item: the SQL, the summary, how the agent ended, and how the query ran on this cohort.

    What the agent can do¶

    The agent's only tool is read-only SQL, run in an isolated worker process (SQLSandbox).

    What the worker accepts: - Exactly one statement of type SELECT: SELECT, WITH, FROM, DESCRIBE, SUMMARIZE or SHOW. No DDL, COPY, ATTACH, SET, INSTALL or multi-statement strings. - Statements run with DuckDB's file and network access disabled, extension loading and installing off, and the configuration locked.

    How the worker is isolated: - It opens the database before any model SQL runs: a file read-only, or in-memory tables sent over a pipe and never written to disk. - It then installs a seccomp allowlist with no open, socket or process creation. - An address-space limit, DuckDB's memory limit and a per-statement interrupt bound each statement. The worker is killed if it stops answering. - Results are capped in rows and characters.

    What the agent cannot do: it has no files, shell, network, Python or browsing. Model-written SQL never runs in the calling process.

    Store profile and search¶

    Every requirement used to start by rediscovering the same facts and hunting for spellings with ILIKE queries. Two code-made aids replace that (matchminer_ai.patients.workup_sql.profile). Both run code-written SELECT statements in the same worker, over the same tables.

    Store profile (store_profile, render_profile; about 7,000 characters for a 1,000-patient store). Computed once per process and exploration database, it gives: - patients, notes and incomplete extractions; - per item table: rows at each level, patients, planned items, items with an exact stated date, and undated items; - patients per code of every code column (codes with no items are left out); - patients per cancer site group, and how many of them have stage IV, M1 or distant extent documented. Code matches primary_site and histology text against fixed patterns (SITE_GROUPS), so the groups are approximate. The agent is told to use them only to judge plausibility, never in a final query.

    search (search_values). The agent gives up to max_search_terms (8) words or word stems. Code returns: - every code whose code or meaning contains one, with its patients; - every distinct value of every text column that contains one, rare values included, with item and patient counts, most patients first. Values that differ only in case are merged. At most max_search_rows (50) are shown, and per-column totals show what was cut.

    A search after a valid submission counts as a checking query.

    The profile is a function of the database and of PROFILE_VERSION, which is in the agent contract, so the cache key (which holds the database fingerprint) covers it. Like exploration results, both reach the agent's endpoint: aggregate counts and distinct extracted values, never patient ids, note text or quotes.

    The database¶

    Columns come from the item type declarations (table_columns), never from the data. A query written against one database therefore runs on any other database of the same DATABASE_VERSION (mmai-extraction-sql-v2).

    Every item table starts with these shared columns: - item_key, patient_key, item_type, level, note_id, note_date, document_type. - occurrence: performed or planned. - The primary date as date_value, date_precision, date_source, date_bound, date_lo and date_hi. - A code-made label.

    Then each field of the type: - List fields become VARCHAR[]. - Unstated text becomes NULL. - Each date field x also gets x_lo and x_hi.

    Date intervals follow the compiled-query evaluator's rules: - A month or year spans its whole period. - An undated mentioned item was on or before its note (date_lo NULL). - An undated planned item is on or after its note.

    patients carries reference_date, which by default is the latest note date. It also carries the extraction's completeness (extraction_incomplete, notes_without_records) and extracted_item_types: the item types every one of the patient's records was extracted for. Records of an older extraction schema lack some types; v1 records have no lab tests or counseling. extraction_coverage counts the covered patients per item type.

    Privacy: the tables hold no patient ids (patients are numbered) and no note text. Evidence quotes stay in Python and are attached to results by item_key.

    Results and overrides¶

    The final query returns these columns: - patient_key - status and reason, one of the pairs met/documented, not_met/not_documented, not_met/planned_only, unknown/uncertain_dates, unknown/fields_not_stated, unknown/anchor_unavailable, not_applicable/documented_not_applicable or, only for a requirement that advises against its step, done_not_recommended/documented_not_recommended - applicability - evidence_item_keys - detail

    Code checks that the query returns one row per patient, that the values are valid, and that every cited key is one of that patient's items.

    Steps the guideline advises against ("FDG-PET/CT not routinely indicated"). The agent submits these with recommends_against: true: - A patient who had the step anyway is done_not_recommended, never met. - The aggregate reports their count and no completion fraction (recommends_against on the row).

    Code then applies the compiled-query method's overrides: - no extraction records gives unknown / no_extraction; - an incomplete extraction turns not_met into unknown / incomplete_extraction; - so does a query that reads an item table the patient's records were never extracted for (for example lab_tests on v1 records): an empty table there says nothing; - a requirement the agent declared not expressible gives unknown / not_expressible; - a missing or failed query gives unknown / query_unavailable.

    aggregate_extraction_workup counts the results, as for compiled queries.

    Rules the agent follows¶

    The system prompt (patient.workup_sql.system.txt) holds the full rules. The main ones: - Timing: any time up to the reference date counts unless the requirement is defined by timing relative to an event. Phase labels such as "initial evaluation" set no window. - Undated anchors: when the anchor event has no exact date, it is dated by the first note that mentions it, and a step dated before that note counts as before the event. - Labs: a lab requirement is met only when every lab it names is documented. Tumor markers are biomarkers. - History and physical is always done and is ignored inside combined requirements. - Population: neither the population nor its site is re-checked. Items about an unrelated cancer are excluded through cancer_ids, never through lists of site words.

    Privacy¶

    What reaches the endpoint: exploration results are patient-derived extracted values. They are never patient ids, note text or evidence quotes. They reach the configured LLM endpoint. Use only an endpoint authorized for the records the exploration database was built from, the same rule as for note-reading reviews.

    What reaches no LLM: evaluating a cohort makes no model calls.

    What the cache keeps: the SQL, the summary, approximations, the exploration steps' SQL and outcomes, and aggregate counts (distribution). It never keeps query results.

    Settings, budget and caching¶

    Section and endpoint: the workup_sql_agent preset section configures the agent. - It needs an OpenAI-compatible endpoint (remote.enabled): a local vLLM server, Vertex or another provider, or Claude through a Databricks AI Gateway (below). It cannot drive an in-process engine. - The section's remote may set its own server_urls, provider, google_project_id and databricks_profile, overriding config.remote for the agent alone. The other sections (such as extraction) keep the shared connection. - The context window comes from context_window, else local.engine.max_model_len, else the endpoint's /v1/models.

    Claude through a Databricks AI Gateway (provider databricks_anthropic): - Install: pip install 'matchminer-ai[databricks]' (the anthropic and databricks-sdk packages). - Log in once: databricks auth login --host <workspace URL> --profile unity-gateway. The Databricks SDK then gets and refreshes access tokens through the Databricks CLI, which must be on the process's PATH. - Settings: in the section's remote, set: - provider: databricks_anthropic; - server_urls: ["https://<workspace host>/ai-gateway/anthropic"]; - databricks_profile: unity-gateway (or none, for a notebook's or job's identity, or a service principal from ARM_* variables); - model_name: the full three-part endpoint name, such as ai_gateway_model_services_prod.<team>_<project>.<team>_<project>-claude-sonnet-5-5; - request_params: max_tokens and reasoning_effort, which becomes Claude's effort (low to max); - extra_body: {}.

    Also set the section's sampling_profile: none and context_window (1,000,000 for Sonnet 5.5). The gateway has no /models or tokenizer route, so prompt budgets use bytes. - What is sent: requests go through the official Anthropic SDK to the Messages route, with structured outputs (output_config.format). - Schema limits: the SDK moves limits Claude does not enforce, such as maxItems, into descriptions. The harness still validates them in code. - Caching: the instructions are a cached system block. The turn's response schema follows in a second block, because its allowed actions change from turn to turn. - Refusal fallbacks: Opus and Sonnet 5.5 requests opt into server-side fallbacks (fallbacks: "default"), so a declined turn is answered by another Claude model. - Credentials: the token goes only to the gateway URL, whose host must be the profile's workspace. A missing or expired login fails the run at once with a login hint. Other failures keep only their HTTP status. - Scope: only structured requests support this provider; other stages reject it.

    limits: - max_actions (12) and max_submits (3) bound the run. - The agent is asked to submit a first candidate by submit_by (6), so that it reviews results rather than spending the budget exploring. - After a valid submission it may run at most max_review_queries (3) checking queries. Code then removes the query action: the agent accepts the submission, or submits a revision that fixes a defect it found, which allows 3 more. - max_rows, max_cell_chars and max_result_chars bound what it sees of each result; max_search_terms and max_search_rows bound a search. - max_recent_steps sets how many recent steps are replayed with their results. Earlier ones are listed by outcome, and the agent's own memory carries the rest. - Up to max_concurrent_items (8) requirements are explored at once, sharing one worker; the agent's request cap is raised to match. activity_callback reports which requirements are being explored and the turn each is on. - A stalled request is retried after request_timeout (600 s) instead of the shared remote.request_timeout.

    Ending a run: - A valid submission on the last turn is accepted, with a limitation saying so. - When the budget (or the context window) runs out after a valid submission whose revision was not valid, the last valid submission is used, with limitations saying so. - If no valid submission is made, the entry fails and its results are unknown.

    Caching: distinct requirements are explored once per call. Pass cache (any mapping) to reuse accepted queries. The key (workup_sql_cache_key) covers: - the requirement text and the population context; - the exploration database's fingerprint; - the agent, database, store-profile and extraction-schema versions; - the prompt and response-schema hashes; - the provider, model and reasoning effort that write the queries (agent_llm_identity), so each model's and effort's queries are cached apart.

    Failed runs are saved under their key too, but never reused: the next call explores the requirement again and overwrites the entry. A saved failure keeps what is needed to diagnose it: - its steps (SQL and outcomes; an invalid submission names its problems, such as invalid: patients without a row, never values or error text); - error, which says how the run ended; - diagnostics: counts of the harness's own messages for invalid answers, of finish reasons (length means cut off at the token limit), and of transport failures by HTTP status. Never provider text, prompts or results.

    Each explored requirement is also logged in one line (requirement name, how the run ended, actions, seconds, requests and prompt tokens): INFO for an accepted query, WARNING for a failure.

    matchminer_ai.patients.workup_sql ¶

    SQL-agent workup checks: an LLM writes one cohort-level SQL query per workup requirement.

    A research review aid beside the compiled-query method (:mod:matchminer_ai.patients.workup_queries). Structured extraction records become relational tables (:func:build_extraction_database, written to DuckDB by :func:write_extraction_database). For each guideline workup requirement, an LLM agent explores an exploration database with read-only SQL in an isolated worker. It sees codes, spellings and distributions, submits a final query, sees that query's results over the whole exploration population, and accepts or revises it (:func:compile_workup_sql). Code counts what the store holds first (:func:store_profile, in the agent's prompt), and the agent's search action (:func:search_values) lists the codes and text values containing a few words. The agent's only power is read-only SQL: no files, network, shell or other tools. Code then runs each accepted query once over every cohort it is applied to (:func:check_workup_with_sql) and reports met, not met (not documented), unknown or not applicable, with the cited items' evidence quotes.

    Exploration results are patient-derived extracted values (never patient ids, note text or evidence quotes) and reach the configured LLM endpoint. Use only an endpoint authorized for the records. Results need human review against the source notes. Requires the optional duckdb dependency (pip install matchminer-ai[sql]).

    class SQLSandbox:
    """A loaded, isolated DuckDB worker. Thread-safe: statements run one at a time.

    Pass ``database_path`` (a file from
    :func:`~matchminer_ai.patients.workup_sql.write_extraction_database`) or
    ``database`` (an :class:`ExtractionDatabase`, loaded in memory).
    ``info`` is the file's ``database_info`` table (empty for in-memory tables).
    """

    def __init__(self, *, database_path=None, database=None, limits: SandboxLimits | None = None):
        if (database_path is None) == (database is None):
            raise ValueError("Pass exactly one of database_path or database.")
        if sys.platform != "linux":
            raise SQLSandboxError("The isolated SQL worker requires Linux and libseccomp.")
        check_cancelled()
        self.limits = limits or SandboxLimits()
        self.lock = threading.Lock()
        payloads, tables, statements = [], [], []
        if database is not None:
            for name, table in database.tables.items():
                data = _arrow_bytes(table)
                payloads.append(data)
                tables.append({"name": name, "bytes": len(data)})
            statements = database.statements()
        setup = {
            "database": str(Path(database_path).resolve()) if database_path is not None else None,
            "tables": tables,
            "statements": statements,
            "memory_mb": self.limits.memory_mb,
            "duckdb_memory_mb": self.limits.duckdb_memory_mb,
        }
        self.process = subprocess.Popen(
            [sys.executable, "-I", "-S", str(Path(__file__).with_name("_sql_worker.py")),
             json.dumps(_package_paths())],
            stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.DEVNULL,
            env={name: "1" for name in ("OPENBLAS_NUM_THREADS", "OMP_NUM_THREADS",
                                        "MKL_NUM_THREADS", "NUMEXPR_NUM_THREADS")},
            cwd="/", close_fds=True, bufsize=0,
        )
        self.selector = selectors.DefaultSelector()
        self.selector.register(self.process.stdout, selectors.EVENT_READ)
        try:
            payload = (json.dumps(setup) + "\n").encode() + b"".join(payloads)
            ready = self._exchange(payload, timeout=self.limits.startup_timeout_seconds)
            if ready.get("ready") is not True or not isinstance(ready.get("info"), dict):
                raise SQLSandboxError("SQL worker isolation unavailable; no SQL was run.")
            self.info = {str(k): str(v) for k, v in ready["info"].items()}
        except BaseException:
            self.close()
            raise

    def _exchange(self, payload: bytes, *, timeout):
        failed = threading.Event()

        def send():
            try:
                view = memoryview(payload)
                while view:
                    written = os.write(self.process.stdin.fileno(), view)
                    view = view[written:]
            except (OSError, ValueError):
                failed.set()

        writer = threading.Thread(target=send, daemon=True)
        writer.start()
        deadline = time.monotonic() + timeout
        chunks, size = [], 0
        try:
            while True:
                check_cancelled()
                remaining = deadline - time.monotonic()
                if remaining <= 0:
                    raise SQLSandboxError("SQL worker exceeded its wall-time limit.")
                if not self.selector.select(min(remaining, 0.1)):
                    continue
                chunk = os.read(self.process.stdout.fileno(), 65536)
                if not chunk or failed.is_set():
                    raise SQLSandboxError("SQL worker exited or its transport failed.")
                size += len(chunk)
                if size > self.limits.max_reply_bytes:
                    raise SQLSandboxError("SQL worker exceeded its output limit.")
                chunks.append(chunk)
                if chunk.endswith(b"\n"):
                    try:
                        reply = json.loads(b"".join(chunks))
                    except (ValueError, UnicodeError):
                        raise SQLSandboxError("SQL worker returned invalid data.") from None
                    if not isinstance(reply, dict):
                        raise SQLSandboxError("SQL worker returned invalid data.")
                    return reply
        except BaseException:
            self.close()
            raise
        finally:
            writer.join(timeout=1)

    def query(self, sql: str, *, max_rows: int, max_cell_chars: int | None = None,
              count_limit: int = 1_000_000, timeout: float | None = None) -> dict:
        """Run one statement: ``columns``, ``types``, up to ``max_rows`` ``rows``,
        ``row_count`` (counted up to ``count_limit``; ``more_rows`` beyond it),
        ``error`` (an exception type name) and ``error_detail`` (for the model only)."""
        if not isinstance(sql, str) or not sql.strip():
            raise ValueError("Empty SQL.")
        if len(sql) > self.limits.max_sql_chars:
            return {"columns": [], "types": [], "rows": [], "row_count": 0, "more_rows": False,
                    "error": "SQLTooLong", "seconds": 0.0,
                    "error_detail": f"SQL longer than {self.limits.max_sql_chars} characters."}
        timeout = timeout or self.limits.query_timeout_seconds
        request = {"sql": sql, "timeout": timeout, "max_rows": int(max_rows),
                   "count_limit": int(count_limit), "max_cell_chars": max_cell_chars}
        with self.lock:
            if self.process.poll() is not None:
                raise SQLSandboxError("SQL worker is not running.")
            reply = self._exchange((json.dumps(request, ensure_ascii=True) + "\n").encode(),
                                   timeout=timeout + self.limits.kill_grace_seconds)
        expected = {"columns", "types", "rows", "row_count", "more_rows", "error",
                    "error_detail", "seconds"}
        if (set(reply) != expected or not isinstance(reply["rows"], list)
                or len(reply["rows"]) > max_rows or type(reply["row_count"]) is not int
                or not isinstance(reply["columns"], list)
                or any(not isinstance(r, list) or len(r) != len(reply["columns"])
                       for r in reply["rows"])
                or (reply["error"] is not None and not isinstance(reply["error"], str))):
            self.close()
            raise SQLSandboxError("SQL worker returned an invalid result.")
        return reply

    def close(self):
        process = getattr(self, "process", None)
        if process is None:
            return
        if process.poll() is None:
            process.kill()
        try:
            process.wait(timeout=5)
        except subprocess.TimeoutExpired:
            pass
        try:
            self.selector.close()
        except Exception:  # noqa: BLE001
            pass
        for stream in (process.stdin, process.stdout):
            if stream is not None:
                stream.close()

    def __enter__(self):
        return self

    def __exit__(self, *args):
        self.close()

        raise ValueError("patient_ids repeat")

        if not isinstance(record, dict):
            continue

        covered[pid] = covered[pid] & found if pid in covered else found
    columns = {t.name: table_columns(t) for t in types}
    rows: dict[str, list[dict]] = {t.name: [] for t in types}

    patients, documents = [], []
    for pid in ids:
        patient = data.get(pid) or PatientData(pid)
        key = keys[pid]
        for view in patient.items:
            if view.item_type not in by_type:
                continue
            item_key = len(views) + 1
            views[item_key] = view
            row = _common_values(view, item_key, key)
            for column in columns[view.item_type][len(COMMON_COLUMNS):]:
                if column.name in {"relation", "source_of_document"} and view.level != "document":
                    row[column.name] = None
                else:
                    row[column.name] = _field_value(column, view.item)
            rows[view.item_type].append(row)
        reference = reference_dates.get(pid) if isinstance(reference_dates, Mapping) \
            else reference_dates
        if reference is None:
            reference = patient.last_note_date
        value, precision = parse_date(reference)
        reference_day = None
        if value is not None:
            reference_day = _day(date_interval(value, precision)[1])
        patients.append({
            "patient_key": key,
            "reference_date": reference_day,
            "last_note_date": _date(patient.last_note_date),

    def write_extraction_database(path, database: ExtractionDatabase, *, private=False) -> Path:
    """Write ``database`` as a DuckDB file atomically (0600 when ``private``).

    The file holds patient-derived values (no ids or note text): keep it where the
    extraction records may be kept. Requires the optional ``duckdb`` dependency.
    """
    import duckdb

    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True, mode=0o700 if private else 0o777)
    fd, temporary = tempfile.mkstemp(prefix=f".{path.name}.", suffix=".partial", dir=path.parent)
    os.close(fd)
    os.unlink(temporary)  # DuckDB creates the file itself.
    try:
        connection = duckdb.connect(temporary)
        try:
            for name, table in database.tables.items():
                connection.register("_incoming", table)
                connection.execute(f"CREATE TABLE {name} AS SELECT * FROM _incoming")
                connection.unregister("_incoming")
            for statement in database.statements():
                connection.execute(statement)
            info = {**database_info(database),
                    "created_utc": datetime.now(timezone.utc).isoformat(timespec="seconds")}
            connection.execute("CREATE TABLE database_info (key VARCHAR, value VARCHAR)")
            connection.executemany("INSERT INTO database_info VALUES (?, ?)", list(info.items()))
            connection.execute("CHECKPOINT")
        finally:
            connection.close()
        for leftover in (Path(temporary + ".wal"),):
            leftover.unlink(missing_ok=True)
        if private:
            os.chmod(temporary, 0o600)
        os.replace(temporary, path)
    except BaseException:
        Path(temporary).unlink(missing_ok=True)
        Path(temporary + ".wal").unlink(missing_ok=True)
        raise
    return path

    requirements: Sequence[dict],
    *,
    database: str | Path | ExtractionDatabase,
    config: MMAIConfig | None = None,
    population_context: str | None = None,

    ``database``: an exploration database, either a DuckDB file from
    :func:`write_extraction_database` or an :class:`ExtractionDatabase`. The
    agent explores it and checks each submission on all of its patients.
    ``cache``: any mapping from cache keys to entries. Accepted queries are reused

    steps and ``diagnostics``, so that it can be diagnosed; it is never reused, and
    the next call explores the requirement again (and overwrites it). ``llm`` overrides the endpoint

    reports finished requirements; ``activity_callback(items)`` reports, whenever

    "max_actions"}`` each, ``action`` being the turn the agent is on (both are
    called from the calling thread).

    entry has ``cache_key``, ``requirement``, ``status`` (compiled or failed),
    ``expressible``, ``sql``, ``summary``, ``approximations``, ``steps`` (SQL
    and outcomes, no results), ``distribution`` (aggregate counts over the
    exploration population), ``termination``, ``error``, ``usage``,
    ``diagnostics`` (code-made counts of invalid answers, finish reasons and
    transport failures), ``model``, ``contract`` and ``cached``. With ``return_metadata``, also returns metadata.

        fingerprint, extensions = database.fingerprint, database.extensions
        patient_count = len(database.patient_ids)
        items = len(database.views)

            raise ValueError("The extraction database is from another version; rebuild it.")

        raise ValueError("The exploration database has no patients.")

    texts = [requirement_text(r) for r in requirements]

    results: dict[str, dict] = {}
    for key in distinct:

        if reusable_sql_entry(saved, contract):
            results[key] = {**copy.deepcopy(saved), "cached": True}

                                timespec="seconds"),
                        }

        "model": model,
        "compiled_by": sorted({e.get("model") for e in results.values() if e.get("model")}),

        "exploration": {"fingerprint": fingerprint, "patients": patient_count, "items": items},
    }
    return entries, metadata

    """Run every accepted query once over the cohort's records; one assessment per patient × item.

    ``records``, ``patient_ids``, ``reference_dates`` and ``coverage`` are as for
    :func:`~matchminer_ai.patients.workup_queries.check_workup_with_extractions`;
    ``compiled`` is :func:`compile_workup_sql` output, one entry per requirement
    (each with its ``requirement``). Returns ``{"patients", "aggregate", "notice",
    "queries"}``; ``queries`` reports how each query ran on this cohort.
    """
    limits = limits or agent_limits(config or load_default_preset())
    database = build_extraction_database(records, coverage=coverage, patient_ids=patient_ids,
                                         reference_dates=reference_dates)
    ids = database.patient_ids
    progress = progress_callback or (lambda done, total: None)
    runnable = [n for n, e in enumerate(compiled)
                if e.get("status") == "compiled" and e.get("expressible") is not False
                and isinstance(e.get("sql"), str)]
    rows: dict[int, dict] = {}
    failures: dict[int, str] = {}
    runs = [{"status": "not_run"} for _ in compiled]
    progress(0, len(compiled))
    if runnable and ids:
        with SQLSandbox(database=database, limits=limits.sandbox()) as box:
            for done, number in enumerate(runnable, 1):
                check_cancelled()
                try:
                    check = run_final_query(
                        box, compiled[number]["sql"], len(ids), limits,
                        recommends_against=bool(compiled[number].get("recommends_against")))
                except SQLSandboxError:
                    failures[number] = "the isolated SQL worker failed while running this query."
                    runs[number] = {"status": "failed", "problem": "worker_failure"}
                    break
                if check.problems:
                    failed = check.problems[0].startswith("The query failed")
                    failures[number] = ("the SQL query failed on this cohort's records."
                                        if failed else "the SQL query's output broke its "
                                        "contract on this cohort's records.")
                    runs[number] = {"status": "failed",
                                    "problem": "error" if failed else "contract"}
                else:
                    rows[number] = check.rows
                    runs[number] = {"status": "ran", "distribution": check.distribution}
                progress(done, len(compiled))
    for number in runnable:
        if runs[number]["status"] == "not_run":
            failures[number] = "the isolated SQL worker failed before this query ran."
    reference = {pid: row["reference_date"] for pid, row in
                 zip(ids, database.tables["patients"].to_pylist(), strict=True)}
    patients = []
    for key, pid in enumerate(ids, 1):
        patient = database.data.get(pid) or PatientData(pid)
        day = reference[pid].isoformat() if reference[pid] else None
        assessments = []
        for number, entry in enumerate(compiled):
            result = assess((rows.get(number) or {}).get(key), entry, patient, database,
                            reference_date=day, failure=failures.get(number))
            assessments.append({
                "recommendation_index": number,
                "recommendation": copy.deepcopy(entry["requirement"]),
                "name": entry["requirement"]["name"],
                **result,
                "query_key": entry.get("cache_key"),
                "sql": entry.get("sql"),
                "recommends_against": bool(entry.get("recommends_against")),
            })
        patients.append({
            "patient_id": pid,
            "review": {"assessments": assessments, "notice": NOTICE,
                       "metadata": {"method": METHOD, "coverage": patient.coverage()}},
        })
    requirements = [entry["requirement"] for entry in compiled]
    progress(len(compiled), len(compiled))
    return {"patients": patients, "aggregate": aggregate_extraction_workup(patients, requirements),
            "notice": NOTICE, "queries": runs}

    def render_database_guide(extensions: Iterable[str] | None = ()) -> str:
    """The tables, their columns and every column's codes, for the agent's prompt."""
    types = item_types(extensions)

    def block(title, columns, note=""):
        lines = [title + (f"\n  {note}" if note else "")]
        for column in columns:
            name, sql_type, description, *rest = column
            vocabulary = rest[0] if rest else None
            line = f"  {name} {sql_type}: {description}"
            if vocabulary is not None:
                line += " Codes: " + ", ".join(vocabulary.codes) + "."
            lines.append(line)
        return "\n".join(lines)

    blocks = [
        block("patients (one row per patient)", PATIENT_COLUMNS),
        block("documents (one row per note with a document-level record)", DOCUMENT_COLUMNS),
        block("items (view: the shared columns of every item table)", COMMON_COLUMNS),
    ]
    shared = {name for name, _, _ in COMMON_COLUMNS}
    for item_type in types:
        columns = [(c.name, c.sql_type, c.description, c.vocabulary)
                   for c in table_columns(item_type) if c.name not in shared]
        note = f"{item_type.description} Levels: {', '.join(sorted(item_type.levels))}."
        if item_type.guidance:
            note += f" Extraction guidance: {item_type.guidance}"
        date_note = (f" Primary date (date_lo/date_hi): {item_type.primary_date}."
                     if item_type.primary_date else " Dated by its note.")
        blocks.append(block(f"{item_type.key} (item_type '{item_type.name}'; the shared "
                            "columns, then:)", columns, note + date_note))
    blocks.append(block("vocabulary (every code and its meaning)", VOCABULARY_COLUMNS))
    blocks.append(block("extraction_coverage (which item types the records were extracted "
                        "for)", COVERAGE_COLUMNS, "An item type with few covered patients was "
                        "not extracted for most records (an older extraction schema): an "
                        "empty table then says nothing about whether things were done."))
    return "\n\n".join(blocks)

    def store_profile(box: SQLSandbox, extensions: Iterable[str] = ()) -> dict:
    """Counts of what the exploration database holds (code-written queries only)."""
    types = item_types(extensions)
    tables = [t.key for t in types]
    [[patients, incomplete]] = _run(
        box, "SELECT count(*), count(*) FILTER (WHERE extraction_incomplete) FROM patients")
    [[documents]] = _run(box, "SELECT count(*) FROM documents")
    per_table = " UNION ALL ".join(
        f"SELECT {_quote(t)} AS t, count(*) FILTER (WHERE level = 'document') AS doc, "
        "count(*) FILTER (WHERE level = 'patient') AS pat, count(DISTINCT patient_key) AS pts, "
        "count(*) FILTER (WHERE occurrence = 'planned') AS planned, "
        "count(*) FILTER (WHERE date_precision = 'day' AND date_source <> 'note_date') AS exact, "
        f"count(*) FILTER (WHERE date_bound IS NOT NULL) AS undated FROM {t}" for t in tables)
    table_rows = [dict(zip(("table", "document", "patient", "patients", "planned", "exact_date",
                            "undated"), row)) for row in _run(box, per_table)]
    codes_sql = " UNION ALL ".join(
        f"SELECT * FROM ({_values(t, c, is_list)}) WHERE value IS NOT NULL"
        for t, c, is_list in code_columns(types))
    codes_sql = (f"WITH v AS ({codes_sql} UNION ALL SELECT 'documents', 'document_type', "
                 "document_type, patient_key FROM documents WHERE document_type IS NOT NULL) "
                 "SELECT table_name, column_name, value, count(DISTINCT patient_key) AS n FROM v "
                 "GROUP BY ALL ORDER BY table_name, column_name, n DESC, value")
    codes: dict[str, list[tuple[str, int]]] = {}
    for table, column, value, count in _run(box, codes_sql, max_rows=20000):
        codes.setdefault(f"{table}.{column}", []).append((str(value), int(count)))
    groups = " UNION ALL ".join(f"SELECT {_quote(name)} AS site, {_quote('(?i)' + pattern)} "
                                "AS pattern" for name, pattern in SITE_GROUPS)
    sites_sql = (
        f"WITH g AS ({groups}), d AS (SELECT patient_key, coalesce(primary_site, '') || ' ' || "
        f"coalesce(histology, '') AS text, {ADVANCED_SQL} AS advanced FROM diagnoses), "
        "m AS (SELECT g.site, d.patient_key, bool_or(d.advanced) AS advanced FROM d JOIN g ON "
        "regexp_matches(d.text, g.pattern) GROUP BY ALL) "
        "SELECT site, count(*), count(*) FILTER (WHERE advanced) FROM m GROUP BY site "
        "UNION ALL SELECT '(no site group matched)', count(*), 0 FROM patients p WHERE NOT "
        "EXISTS (SELECT 1 FROM m WHERE m.patient_key = p.patient_key)")
    order = {name: n for n, (name, _) in enumerate(SITE_GROUPS)}
    sites = sorted(((str(s), int(n), int(a)) for s, n, a in _run(box, sites_sql)),
                   key=lambda row: order.get(row[0], len(order)))
    return {"version": PROFILE_VERSION, "patients": int(patients), "documents": int(documents),
            "incomplete": int(incomplete), "tables": table_rows, "codes": codes,
            "sites": sites}

    def search_values(box: SQLSandbox, terms: Sequence[str], profile: dict, *,
                  extensions: Iterable[str] = (), max_rows: int = 60,
                  max_cell_chars: int = 160, timeout: float | None = None) -> dict:
    """Every code and distinct text value containing one of ``terms`` (case-insensitive).

    A word of 3 or fewer characters (an abbreviation such as CEA, CT or EGD) matches
    whole words only; a longer one matches anywhere (a stem such as colonoscop).
    Underscores in codes count as spaces.

    Returns ``codes`` (table.column, code, meaning, patients) from the vocabulary,
    ``values`` (table.column, value, items, patients; values differing only in case
    or surrounding spaces are one value; most patients first, at most ``max_rows``)
    and ``columns`` (per table.column: matching distinct values and patients, so a
    cut list is visible). Rare values are included.
    """
    words = [w for w in dict.fromkeys(str(t).strip().lower() for t in terms) if len(w) >= 2]
    if not words:
        raise ValueError("search needs at least one word of 2 or more characters.")
    types = item_types(extensions)
    literal = ", ".join(
        f"({_quote(w)}, {'true' if len(w) <= 3 else 'false'}, "
        f"{_quote(r'(^|[^a-z0-9])' + _literal_pattern(w) + r'($|[^a-z0-9])')})" for w in words)
    match = ("EXISTS (SELECT 1 FROM w WHERE CASE WHEN w.whole THEN regexp_matches(lower({0}), "
             "w.pattern) ELSE strpos(lower({0}), w.word) > 0 END)")
    found = box.query(
        f"WITH w(word, whole, pattern) AS (VALUES {literal}) SELECT table_name, column_name, "
        "code, meaning FROM vocabulary WHERE " + match.format("replace(code, '_', ' ')")
        + " OR " + match.format("meaning")
        + " ORDER BY table_name, column_name, code", max_rows=500, max_cell_chars=None,
        timeout=timeout)
    if found["error"]:
        raise SearchFailed(str(found["error"]))
    vocabulary = found["rows"]
    counts = _code_index(profile)
    codes = [{"column": f"{table}.{column}", "code": code, "meaning": meaning,
              "patients": counts.get(f"{table}.{column}", {}).get(code, 0)}
             for table, column, code, meaning in vocabulary]
    union = " UNION ALL ".join(_values(t, c, is_list) for t, c, is_list in text_columns(types))
    base = (f"WITH w(word, whole, pattern) AS (VALUES {literal}), v AS ({union}), "
            "hits AS (SELECT table_name, "
            "column_name, min(trim(value)) AS value, count(*) AS items, "
            "count(DISTINCT patient_key) AS patients FROM v WHERE value IS NOT NULL AND "
            + match.format("value") + " GROUP BY table_name, column_name, lower(trim(value)))")
    reply = box.query(base + " SELECT table_name || '.' || column_name, value, items, patients "
                      "FROM hits ORDER BY patients DESC, items DESC, table_name, column_name, "
                      "value", max_rows=max_rows, max_cell_chars=max_cell_chars,
                      timeout=timeout)
    totals = box.query(base + " SELECT table_name || '.' || column_name, count(*), "
                       "sum(patients) FROM hits GROUP BY 1 ORDER BY 3 DESC", max_rows=200,
                       timeout=timeout)
    for result in (reply, totals):
        if result["error"]:
            raise SearchFailed(str(result["error"]))
    return {
        "words": words,
        "codes": codes,
        "values": [{"column": c, "value": v, "items": int(i), "patients": int(p)}
                   for c, v, i, p in reply["rows"]],
        "more_values": max(0, reply["row_count"] - len(reply["rows"])),
        "columns": [{"column": c, "values": int(n), "patient_sum": int(p)}
                    for c, n, p in totals["rows"]],
    }
